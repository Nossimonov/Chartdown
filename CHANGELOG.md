# Changelog

All notable changes to the Chartdown language and its reference implementation. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [SemVer](https://semver.org/) (pre-1.0: minor bumps may break). The language specification and the six `@chartdown` npm packages version together — a version number names a spec+implementation pair.

## [Unreleased]

### Changed

- **BREAKING — a value that is plainly an attempted number, and is not one, is refused** ([#375](https://github.com/Nossimonov/Chartdown/issues/375)). `measureToNumber` matches `^(\d+(?:\.\d+)?)` and returns **0** when nothing matches, so a malformed measure was never refused — it became zero and the feature silently disappeared, with `check` reporting `ok`. `width=.5mi` is the one that will actually happen: half a mile is a normal thing to write, the leading zero a normal thing to omit, and the river vanished. `width=1e3` is worse in kind — it parsed `1`, discarded `e3`, and drew **something**, so nothing looked wrong at all. And a negative reached the output as **invalid SVG**: `width=-2` emitted `stroke-width="-54.4"`, `size=-2` emitted `r="-24.32"`, either of which a consumer may respond to by dropping the attribute, dropping the element, or refusing the document. Refusing a negative **pair value** is safe without a list of measure-valued parameters, which is the thing that made this tractable: no pair value is written negative anywhere in the corpus or the spec, and the negatives that ARE legitimate — shape offsets like `(-2,-40)` — are points inside a placement, never a `key=value`. **Deliberately no wider.** A bare word (`width=abc`, `width=mi`) still becomes 0, because it is indistinguishable from `facing=south` without that parameter list — and inventing one would go stale the first time a facet was added, which is the defect class this whole cycle was made of. The issue records the limit rather than the fix pretending to cover it. A second test asserts the **property** rather than that one route to it: no render emits a negative geometry attribute, swept over all nine examples in both modes, with a positive control proving the pattern can match.
- **BREAKING — an explicit unit must be the map's own** ([#376](https://github.com/Nossimonov/Chartdown/issues/376)). Spec 02 §1 has always said *"explicit units are always legal and MUST match the map's unit dimension"*, and `grammar.ebnf` said it too in a parenthetical. Nothing implemented either: `measureToNumber` read the digits and **discarded the unit entirely**. So on a `20x14mi` map, `width=60ft` — a perfectly ordinary thing for a GM to write — drew a stroke **three times the width of the map**, blacking the sheet out. A 5280× error, in silence. `width=1.5km` drew exactly what `width=1.5mi` drew, and `3furlongs` rode through as though the unit had been understood. [#367](https://github.com/Nossimonov/Chartdown/issues/367) did not cause this but made it reachable: a unit-suffixed width used to be `NaN` and drew nothing, so loud garbage replaced quiet garbage. This replaces both. **Refused, not converted** — the owner's ruling. A closed unit table is unavoidable either way, since an invented unit has to be rejected regardless, and refusal needs no table. The diagnostic names the map's unit and both ways out. Scoped by the value's **shape** rather than by a list of measure-valued parameters, because no such list exists and one would go stale the first time a facet was added; `facing=south`, `size=2x2` and `detail=map.cd` are untouched, asserted directly. A map that declares no unit — `extent: 800x600` is grammar-legal — has nothing to disagree with and is left alone. The rule is now in `digest.md`, which had never carried it, so an agent meets it before the error rather than after. No committed example moves; all nine still check clean.

### Fixed

- **A broken share link says so, instead of loading a different map** ([#389](https://github.com/Nossimonov/Chartdown/issues/389)). The playground carries the whole document inside the URL, and a link that was truncated — wrapped by a chat client, clipped by an email footer, copied short — was caught and quietly replaced with the Fairwater Manor demo. The recipient saw a complete, plausible, well-formed map with nothing to suggest it was not the one that had been shared. **A wrong map that looks right is the expensive kind of wrong**, and this was the same defect class as the rest of this release — a malformed input coerced into a credible substitute rather than refused. The editor now shows a document that explains itself, and the explanation is its **title**, so it reaches the rendered canvas rather than only the source. That fallback is a *valid* document on purpose: a comment-only file has no `map:` header, so it would fail to check and greet the reader with *"missing required 'map:' header line"* — noise about the wrong problem. A test asserts it checks clean, since a fallback that errors is its own small defect. The toast says the same thing, but it lasts 2.6 seconds and the whole failure is that a substitute looks legitimate, so the message had to outlive it.
- **A theme's numeric properties are checked** ([#388](https://github.com/Nossimonov/Chartdown/issues/388)). Spec 08 §3's `THEME_PROPS` is a closed set of nine, and only `bank=` was ever validated. The rest were stored verbatim and read later with `Number(...) || <default>`, or pasted straight into an SVG attribute — so a theme could produce output no consumer can render, with `check` reporting `ok`. **`opacity=80` is the one a themer will actually write**, reaching for a percentage: it emitted `opacity="80"`, which consumers clamp to 1, so the darkness wash blacked the whole sheet out — the failure [ADR 0050](docs/decisions/0050-a-pool-that-fills-its-field-is-reported-not-redrawn.md) warns about for a legitimate full-field pool, arriving by a route nothing watched. `width=-4` emitted `stroke-width="-4"`, invalid SVG; `width=abc` silently became the default, so the line the themer wrote did nothing and said nothing. **Warn and drop**, matching `bank=`: the value is discarded so the default applies and the map still renders. A theme is presentation, and refusing a map over a stroke width would be the wrong trade. Unlike a document's `key=value` pairs ([#375](https://github.com/Nossimonov/Chartdown/issues/375)), there was no list to invent — the set is closed by design, which is the whole reason this was tractable where that was not. Every numeric spelling the nine committed themes actually use is asserted legal, so the check cannot be stricter than the corpus it governs. No committed theme moves.
- **A token's `size=` is a measure, finishing the trio** ([#387](https://github.com/Nossimonov/Chartdown/issues/387)). [#374](https://github.com/Nossimonov/Chartdown/issues/374)'s own commit message said *"`light=` has always converted correctly through `measureToCells`; only `width=` was left reading raw digits"* — and that was true of a **third** sibling nobody looked at. At `scale: 5ft`, `size=10ft` **is** `size=2`, and it drew one cell. What made it worse than an oversight: [#376](https://github.com/Nossimonov/Chartdown/issues/376) blesses the spelling on the way past. `size=10mi` on that map errors with *"this map is in ft"*, so the unit check confirms `ft` is the map's own unit, waves `10ft` through, and the reader discards it — the author gets a wrong token and a diagnostic system that has just told them the unit was right. `size=10ft` and `size=2` now render **byte-identically**, and the shared helper is renamed `measureInCells` since it no longer serves only `width=`. A bare `size=2` still means two cells, or `redford-crossing`'s ogre would move. Found by an independent review briefed to hunt the defect's class rather than audit the change in front of it — the third round of that question finding the next instance, after [#374](https://github.com/Nossimonov/Chartdown/issues/374) and [#375](https://github.com/Nossimonov/Chartdown/issues/375).

## [0.8.0] — 2026-08-30

### Changed

- **BREAKING — an `at` that frames nothing is refused, and `chartdown frame` says what its output is** ([#368](https://github.com/Nossimonov/Chartdown/issues/368)). Found by an agent drafting a real map, following the CLI's own output. `chartdown frame` prints `at (10,8) area (-6,-3.5) …`, and spec 05 §4's worked line is `island whidbey : **near shore** at (40,100) area (…)` — it is the RELATION that gives `at` a frame for those offsets to be measured in. Pasted bare, as the command invites, the offsets were read as absolute coordinates: a negative one put the shape at `-246,-143.5`, off-canvas, and `check` said nothing. A marsh simply was not on the map. The anchor is now refused where the shape carries its own points, with a diagnostic naming both ways out — add the relation, or drop the `at` and give absolute points. `frame` prints the form its fragment belongs in, on stderr so the line still pipes. **Not** refused, and the distinction is the whole check: `near <ref> at (…) area (…)` and `on <ref> at (…) area (…)` are the spec's own forms, and a SIZED blob — `forest wood : blob at (200,150) size=120mi` — has no points, so its `at` is the placement ([ADR 0025](docs/decisions/0025-a-blob-declares-an-extent-not-an-outline.md)). The first version of this check refused that too, and the existing suite caught it. Breaking because a document that checked clean now errors; no committed example uses the form, and none has a negative shape coordinate at all. Whether a bare `at (x,y)` **should** frame a shape without a referent is a language question, filed separately — it is what `frame` implies and what a traced coastline wants, and it belongs in a proposal rather than inside a bug fix.
### Added

- **The renderer's answer is data before it is ink** ([#355](https://github.com/Nossimonov/Chartdown/issues/355), [ADR 0051](docs/decisions/0051-the-renderers-answer-is-data-before-it-is-ink.md)). `@chartdown/render-svg` gains **`resolveScene(doc, options)`**, and `render` is refactored to consume the same pass. `render` returned `{ svg, diagnostics }` and nothing else, so a host that wanted to draw a Chartdown map with its own primitives — a native app, a canvas widget, an editor that hit-tests what the reader clicked — had to derive resolution a second time from an AST that hands placements over unresolved by design. One host did, and stopped at the boundary of `morphology.ts`: half-planes, placed morphology, organic finishing, label arbitration. That is not a gap in effort, it is 1,192 lines of decisions this repo has already made once, in ADRs — and a second implementation of them produces the failure the spec names more often than any other, a construct that renders identically to its own absence. `sea "The Argen Sea" : west of coast` drew as a ten-point dot; it now resolves to a 404-point polygon carrying `from: {halfPlane: "west", of: "coast"}`. **The data already existed**: `renderRegion` resolved a whole scene per call and discarded it when the function returned, which its own two-pass header comment has always said. So the first pass is now a function with a name (`resolveRegionGeometry`), the scene is a view of it, and the alternative shape — a second pass that re-derives — is the drift [ADR 0010](docs/decisions/0010-uvtt-export-caller-raster.md) rejected outright. **What the scene carries is decided by [ADR 0037](docs/decisions/0037-geometry-is-in-map-units-ink-is-in-canvas-units.md)'s split, and that rule is the whole membership test**: geometry and identity, in the map's own units — the `extent:`'s units on a region, cells on a battlemap, hexes on a hexcrawl — and no stroke widths, no font sizes, no [ADR 0035](docs/decisions/0035-a-label-has-a-legibility-floor.md) legibility floor, no zone insets, no glyph scatter, because a theme *document* is already the interchange format for those and a canvas number would move under `detail:`. A grid map's geometry is a **cell union** rather than an outline, since a structure occupies cells and 06 §3 derives the outline from them, so the derived perimeter rides along; a battlemap also carries `walls` from the same `walls.ts` the light engine reads. A **multi-level battlemap is one scene** carrying `levels` with every feature tagged, `options.level` narrowing it — `render` stacks panels and `exportUvtt` takes one file per level, but a scene is what a host draws *from*, and it should not make a host learn the level names elsewhere first. **Two exclusions, stated rather than implied.** Placed labels are not in v1: a feature carries where its label *wants* to go, not where arbitration put it, so two implementations put the same things in the same places and label them differently — arbitration is interleaved with emission across ~1,400 lines and the placer is stateful, so hoisting it decides a second thing. And **`detail:` is an input to the determinism contract on a region**: organic finishing runs in canvas space (`organicOutline` skips an edge shorter than `QUANTUM`, 0.01 of a canvas *pixel*), so a larger canvas grows texture and the dependence propagates through relational placement — `examples/vessany`'s coast has 400 vertices at `overview` and 665 at `reference`, and four of its seven points shift with it. That is the cost of exporting what is **drawn** rather than what was **declared**, which this export chooses deliberately, since exporting the declaration would hand every host [ADR 0025](docs/decisions/0025-a-coastline-earns-its-texture.md)'s job and produce two coastlines for one document. Grid maps have no such knob and are unaffected. **Half-plane clipping moves from the emit pass into the resolve pass** — the one real behaviour change, and it moves no output: all nine examples render byte-identically in both modes under every theme committed beside them, and that is not luck, because the emit pass never mutates a resolved course. `battlemap.ts`'s `halfPlaneArea` stays where it is: it is a wash polygon built from the drawn course and extended past the terminal cells' centres ([#145](https://github.com/Nossimonov/Chartdown/issues/145)) so the fill meets the band it hides under, which decides how terrain is *painted* rather than where it *is* — the battlemap's coverage was already pure in `grid.ts`. The schema is `packages/render-svg/scene.schema.json`, documented in that package's README and **versioned with the package, not with `SPEC_VERSION`** — a renderer output is not language, so spec 06 §9 gains only a non-normative pointer beside the UVTT mapping. `examples/gumdrop-vale/gumdrop-vale.scene.json` is a worked example, with a test that keeps it current. Not breaking: a purely additive API changes no default and breaks no contract, per the third clause as [CONTRIBUTING](CONTRIBUTING.md) now reads it.

### Fixed

- **Nothing states a version it can derive** ([#365](https://github.com/Nossimonov/Chartdown/issues/365)). An independent review, asked to hunt for [#363](https://github.com/Nossimonov/Chartdown/issues/363)'s defect *elsewhere* rather than to check its fix, found seven more instances. The worst: **`@chartdown/mcp` introduced itself to every host as `version: "0.2.0"`** in the MCP initialize handshake, at 0.7.0, already compiled into the published bundle — the same stale 0.2 as #363, on the surface `llms.txt` recommends as *"the best agent experience"*. It now reads its own `package.json`, and a test refuses any version literal in shipped source, because a version that is **derived** cannot go stale and one that is stated always can. Also corrected: `@chartdown/browser`'s README pinned `@0.1` on its public npm page while the identical snippet in the root README was guarded one file away; six example READMEs claimed `spec v0.6` — a defect [#352](https://github.com/Nossimonov/Chartdown/pull/352) *created* by replacing a stale `v0.1` with a hardcoded `v0.6`; `chartdown_frame` was missing from both places an agent reads the tool list; the changelog said four published packages where the README said six; and the README called `gumdrop-vale` a hexcrawl when it is a region map. The version-agreement list is now derived too — it had hand-listed `action` (private, unpublished) and omitted `measure` (published). Both holes the reviewer demonstrated in #363's own guard are closed: a reworded version claim no longer escapes, and the corpus sentence is checked as well as its numeral.
- **`llms.txt` states the shipped version and the real corpus** ([#363](https://github.com/Nossimonov/Chartdown/issues/363)). Served at the site root, it is the **first** file an agent reads — ahead of the digest it points at — and it said *"it is the whole **v0.2** language"* at 0.7, and *"**five** complete documents"* against a corpus of nine. Found by the owner writing a map for an actual game, which is the one test nothing in CI performs. Three gaps behind it: `npm run bump` had never been told about the file, so its version went stale at every release since 0.2 and would have again at 0.8; nothing connected the example list to `examples/`; and [#331](https://github.com/Nossimonov/Chartdown/issues/331)'s version-claim test — built for precisely this defect — read a **hand-kept** list of four files that did not include it. All three are closed: `bump` rewrites it, the count is checked against the corpus the way [#278](https://github.com/Nossimonov/Chartdown/issues/278) checks the playground picker, and the claim test's file list is now **derived** from `docs/spec/` plus the two root entry points, so a new spec section joins the sweep by existing rather than by being remembered.
- **A battlemap `width=` is a measure too, and the ground now agrees with the ink** ([#374](https://github.com/Nossimonov/Chartdown/issues/374)). [#367](https://github.com/Nossimonov/Chartdown/issues/367) fixed this on region geometry and claimed the corpus had no other exposure. It did — two battlemap river paths — and the battlemap had the same `Number(<measure>)` read in **two** places. `Number("15ft")` is NaN, so the ink went NaN; and in `surfaceCells` it fell through `|| 1` to a **one-cell band**. That second half was the worse one. `surfaceCells` exists so *"the lints, the wall collector and the UVTT exporter cannot disagree about what ground a cell has on it"* — and they did: three cells to the author, `NaN` to the ink, one cell to everything reasoning about ground. A door opening onto a `width=15ft` road reported **`door-onto-void`**, and a UVTT export carried the same disagreement in silence. At `scale: 5ft`, `width=15ft` **is** `width=3`, and `light=20ft` on the same map always converted correctly — `ft` was first-class for everything but `width=`. Both now read through one unit-aware helper, and the scale rides on the shared context whose whole purpose is that these consumers agree. The conversion is deliberately unit-aware: a bare `width=2` still means two cells, or both corpus rivers would move. A test asserts that directly. Found by an independent review asked to hunt for the same defect elsewhere rather than to audit the fix — which is how the corpus claim in #367 turned out to be wrong, and the wrong reason is what had pointed away from this code path.
- **A region `width=` is a measure, not a pixel count** ([#367](https://github.com/Nossimonov/Chartdown/issues/367)). Found by an agent drafting a real map. Spec 05 §4 says `width=<measure>` and `grammar.ebnf` has `measure = number , [ unit ]`, so `1.5mi` and `1.5` are one thing said two ways. Both were wrong, in opposite directions. `Number("1.5mi")` is **NaN**, written straight into `stroke-width="NaN"` — invisible in most rasterizers, with `check` reporting `ok`. And `Number("1.5")` was passed through as 1.5 **canvas pixels**: a hairline on a 20-mile map and the same hairline on a 40-mile one, so the breadth of a marsh did not depend on the map it was drawn on. A band's breadth is how wide the marsh **is** — geometry, which [ADR 0037](docs/decisions/0037-geometry-is-in-map-units-ink-is-in-canvas-units.md) puts in map units. Both now resolve through the conversion the ridge path always used, which is precisely why ridges were the only region geometry whose width worked, and why `ridge … width=5mi` rendered correctly on the very document where the river did not. Doubling `extent:` now halves the drawn breadth, asserted the way ADR 0037's own sweep asserts it for shapes. The **fallback** stays in canvas units deliberately — it is not a measure anybody declared, it is the ink weight a line gets when nothing says otherwise. No committed example moves — but not for the reason first given here: the corpus has **six** `width=` declarations, four ridges and two battlemap river paths, and it is the battlemap path that this change does **not** touch. The two move nothing because they are bare numbers, which the battlemap already read correctly; a unit-suffixed width there is still NaN, tracked separately. Read as a fix rather than BREAKING under ADR 0041's own worked example — *a change that repaints every map* is explicitly excluded, and the declaration's specified meaning never changed; only the renderer's reading of it did.

## [0.7.0] — 2026-08-22

### Changed

- **BREAKING — a document path is a token, not a substring** ([#323](https://github.com/Nossimonov/Chartdown/issues/323), [ADR 0047](docs/decisions/0047-a-document-path-is-a-token.md)). `checkInset` parsed its header with `/^(\S+)\s+at\s+(\S+)$/`, and `\S+` admits no whitespace and understands no quoting. Two failures fell out of that one line. A path with a space **could not be written at all**, and quoting did not rescue it — the quotes are just more characters inside a `\S+` that still cannot span the space. Worse, a quoted path **without** a space checked `ok` while abandoning the seam behind a warning: the quotes were never stripped, so the lookup key was `'"parent.cd"'` and matched no supplied document, and the checker reported a parent that **was** provided as missing — precisely the silent drift that spec 03 §4's requirement to declare the relationship at both ends exists to prevent. The cause was a round-trip rather than a strict regex. The lexer already implements the right rule: `tokenize` treats a quoted string as one token and strips its quotes. The header builder then **re-serializes those tokens back into a string**, putting the quotes back — so the regex was choking on quotes this parser had itself re-added. `checkInset` now consumes that value as tokens, which is lossless precisely because the serializer re-quotes. That repairs the entity half for free, and that half was a plain spec violation rather than a new spelling: `grammar.ebnf` has always defined `ref = word | string`, and `checkInset` compares against `e.name`, so `inset: parent.cd at "The Chipped Tankard"` was always meant to resolve — `\S+` refused it. A **bare** path containing a space stays an error by decision and not by omission: `at` is the separator, so `inset: The Parent.cd at tavern` cannot be split without guessing, and a file named `at.cd` has no reading at all. Quoting is the only unambiguous spelling, and the diagnostic now says so — naming the fix — rather than reciting the form. `grammar.ebnf` gains `doc-path` as a definition where it was previously only named. Breaking under [ADR 0041](docs/decisions/0041-breaking-means-a-clean-document-stops-checking-clean.md): a document whose `inset:` names a quoted path checks clean today **because its seam is not validated**, and once it is, disagreements that were always present — a missing `detail=`, a missing `detail-at=`, a non-integer magnification, an under-covering child grid — start failing loud. There is no way to fix the silent half without that, since the whole complaint is that checks were being skipped. **No committed example moves** — no document in `examples/` uses `inset:` at all, which is also why the corpus cannot evidence this change and the unit coverage carries it instead. `use:` carries the same silent mismatch on a third surface — it does no lexing at all, so the whole header value is the key and `use: "My Lib.cd"` reports a library not provided while it is — and is left to [#324](https://github.com/Nossimonov/Chartdown/issues/324), which answers `doc-path` for every surface at once.
- **BREAKING — a cell address on a gridless map is refused, not dropped** ([#325](https://github.com/Nossimonov/Chartdown/issues/325), [ADR 0049](docs/decisions/0049-a-cell-address-on-a-gridless-map-is-refused-not-dropped.md)). Spec 02 §2 titles the cell address *"one form for every **grid**"* and reads its geometry from *"the header's `grid:` declaration"*; a `region` map declares none, so `C4` written on one names nothing at all. The parser accepted it anyway and the region renderer's placement loop had no branch for `address`, `range` or `edge` — so the placement evaporated and the entity kept its default of nothing. **Five distinct spellings rendered byte-identically to their own absence**: a bare address, an `at` address, an `on … at` payload, and a `[labels]` override's `at` and `sprawl` targets. A sixth was worse rather than merely silent — `area C4..D5` filtered its arguments down to the points among them, found none, assigned the empty list anyway, and emitted `<polygon points=""/>`, an element no renderer can draw. The seventh was already handled: `region.ts` refused a cell in a course's `via` payload ([#258](https://github.com/Nossimonov/Chartdown/issues/258)) and nowhere else, which is exactly what made the other six look deliberate. That special case is now **deleted** rather than kept beside the general rule — one line deserves one diagnostic — and the refusal moved into the core parser beside `checkNoCorner`, so it holds for every consumer of `parse()` whether or not it renders, and the region renderer loses a branch rather than gaining one. The grid-flavoured checks are suppressed on a gridless map: *"place it on the cell instead: `C4`"* is advice the document cannot take. Refused rather than approximated, for the reason [ADR 0043](docs/decisions/0043-an-address-form-a-slot-cannot-consume-is-refused.md) refuses a corner — reading `C4` as world units substitutes an address form the author did not write, and three units into a thousand-unit extent is the northwest corner, so the map would gain a landmark in the wrong place rather than lose one. `grid:` on a gridless map now **warns** where it previously said nothing at all, the mirror of `detail:` on a battlemap ([ADR 0020](docs/decisions/0020-render-resolution-is-editorial.md), [#287](https://github.com/Nossimonov/Chartdown/issues/287)): the map draws correctly without it, so the author loses nothing — and it does not rescue the address, nothing downstream of a gridless map ever reading it. **Breaking** under [ADR 0041](docs/decisions/0041-breaking-means-a-clean-document-stops-checking-clean.md) because a document writing `forest w : at C4` on a region map checked clean and now errors — but what breaks is a document that was already not getting what it asked for, and **no committed example moves**: the corpus renders 18 SVGs (9 map documents × both modes) byte-identically before and after, none of the three region documents in `examples/` writes an address or a `grid:` line, and neither do the two region documents in the vaults. Two neighbours were measured and deliberately left alone rather than folded in: `detail-at=C4` on a region map is still accepted (a gridless parent has no cell for a sub-map's A1, but `detail=` seams are spec 03 §4's mechanism with their own open question about what a gridless seam anchors to), and `area (100,100) (200,200)` — no address anywhere — still checks clean and still draws a two-vertex polygon, a live silent defect reachable with points alone that wants spec 05 §4's *"an outline needs at least three"* warning.

### Fixed

- **Where courses meet, they merge** ([#314](https://github.com/Nossimonov/Chartdown/issues/314), [#315](https://github.com/Nossimonov/Chartdown/issues/315), [ADR 0044](docs/decisions/0044-where-courses-meet-they-merge.md)). One confluence failing two ways. A **joining course ran past the course it joined**: a grid course's points are cell centres and each terminal point is pushed out to its cell's face so the course fills the cell it ends in — right for a stream running into a pond, wrong for a `join`, where the cell belongs to the trunk, so the course came out the far side exactly `CELL/2` past the centreline with a squared cap standing in open floor. And **every course's bank was drawn over every earlier course's water**: a themed course emits a wide edge band then a narrower core, per entity, in document order, so a junction became a lattice of banks over the water — invisible under the default theme, which gives a course no `edge=`, and obvious the moment anyone banked a river. A joining end now stops at its meeting point, and every bank is drawn before any water. Neither fix works alone. The region renderer follows separately: its courses carry bank and coast masks and its coastlines are courses too, so reordering there would move geometry [ADR 0034](docs/decisions/0034-a-border-lies-on-one-side-of-its-line.md) and [#165](https://github.com/Nossimonov/Chartdown/issues/165) depend on. *(This landed 80 minutes after the `v0.6.0` tag and was filed under it by mistake; it shipped in no release until this one — #351.)*
- **An example whose only way in is a secret** ([#333](https://github.com/Nossimonov/Chartdown/issues/333)). Two fixes in a row — [#320](https://github.com/Nossimonov/Chartdown/issues/320) and [#319](https://github.com/Nossimonov/Chartdown/issues/319) — reported that the whole corpus was byte-identical, and each said plainly that this was **containment rather than cover** ([#295](https://github.com/Nossimonov/Chartdown/issues/295) hit the same blind spot earlier without making a corpus claim): every committed example drew its secrets as *additions* — a GM-only token, a trapped strongbox, an assassin in a room the party can already enter — and none had a secret that was the sole means of access. That is exactly where redaction and reasoning diverge, so the corpus was systematically blind to the one class of defect that kept being found by hand. `examples/greyhallow` is a parish chapel with a crypt, spelling a secret three ways: a **reliquary whose only door is `hidden`** (the lints must read the declared model, ADR 0045), a **double declaration** — a trapdoor `hidden` in the nave and a plain stair at the same cell below, which is the one-sided secret idiom (ADR 0046) — and a **lone `hidden` connector**, the sexton's bolt-hole, which must project a landing nowhere. The committed pair is the assertion: the GM sheet annotates all three, and the player chapel panel carries **no annotation at all**, which requires three separate mechanisms to hold at once. **And it can fail** — reverting #319's guard makes `▼ crypt` appear on the player sheet and moves the committed render, which is the property a corpus addition needs and the reason the previous corpus proved nothing here.
- **A renderer invariant is reported, not thrown at the caller** ([#341](https://github.com/Nossimonov/Chartdown/issues/341)). [ADR 0043](docs/decisions/0043-an-address-form-a-slot-cannot-consume-is-refused.md) made an unhandled edge direction a loud failure rather than a silent east edge, and `edgeSegment` throws on a corner — correct, and nothing caught it. Because `check` renders unconditionally ([#120](https://github.com/Nossimonov/Chartdown/issues/120)), `wall : C3.nw` killed the process before the print loop, so the author of a corner-placed wall or door got a Node stack trace and **no diagnostic at all** — from `check`, the command CI runs. The bitter part is that the right message already existed and was discarded: the parser had refused `C3.nw` by name (*"nothing in the language is placed on a corner"*) before the renderer ever ran. The archetype decided whether it crashed, since that decides whether the renderer reaches `edgeSegment` at all: a `statue` on a corner reported two clean errors while a `wall` or a `door` on the same cell aborted. The throw is unchanged and still loud. What changes is that `render` catches it and returns it as a diagnostic the caller can print, reported as a **renderer** fault distinct from the document's own errors — an invariant that fired means the renderer met something it believes impossible, and flattening that into an ordinary error would make the next one read as the author's mistake. The guard sits in `render` rather than in the CLI because three products outside this package call it — the CLI, the Obsidian plugin and the MCP server — and in a plugin an uncaught throw is worse than a stack trace: a dead pane with no line number. Diagnostics earned before the throw survive it, and a document that draws gains nothing.
- **The coherence lints read the document, not the redaction of it** ([#320](https://github.com/Nossimonov/Chartdown/issues/320), [ADR 0045](docs/decisions/0045-a-redaction-is-not-the-document.md)). Spec 06 §10's six checks reason about what a document **means**, and they were handed the **mode-stripped** model — so a player render linted its own redaction. Strip the only way into a room and the room has no way in, so **every secret entrance in Chartdown reported `unreachable-room`**, on three lines with no `levels:` and nothing exotic: `building vault: A1..B2` with `door secretdoor : on vault at B2.s hidden` checked `ok`, rendered clean in GM, and warned in player. Three things made it worse than ordinary noise — it **arrived by default**, since `render` defaults to player; it **could not be silenced**, since §10 has no suppression syntax, deliberately; and its **advice was destructive**, because the one edit that cleared it — give the room a real opening — is the edit that destroys the secret. That last is the failure [#128](https://github.com/Nossimonov/Chartdown/issues/128) already ruled on once. Spec 06 §10 now states a fourth rule beneath its lint table — **a redaction is not the document** — normatively: `hidden` and `[gm]` decide what a *reader* is shown, not what the document *says*, and a renderer whose lint set depends on the render mode is non-conforming. The CLI had already reached this position in one place without generalising it, running `check`'s internal render in GM mode with the comment *"GM mode, so nothing is skipped."* **Nothing drawn moves**: all 18 corpus renders (9 map examples × both modes) are byte-identical, and the corpus emits no warnings, before or after — because no committed example has a room whose only entrance is secret, which is how this shipped. What is **not** fixed here is the sibling defect on the reciprocal-landing path, where a hidden connector is replaced by an automatic landing and the secret leaks onto the drawn sheet ([#319](https://github.com/Nossimonov/Chartdown/issues/319)); it wants the same declared entity set, which is now on `LevelContext` for it, but it moves rendered output and this change's whole claim is that nothing rendered moves.
- **A landing is suppressed by a declaration, not by a drawing** ([#319](https://github.com/Nossimonov/Chartdown/issues/319), [ADR 0046](docs/decisions/0046-a-landing-is-suppressed-by-a-declaration-not-by-a-drawing.md)). The sibling defect the entry above names, and it failed in the hard direction: by **adding** the secret to the players' sheet rather than omitting something. Spec 06 §8 offers one convenience — *"the destination panel shows the reciprocal landing automatically unless an explicit connector is declared at that cell"* — and spec 01 §6 one guarantee, that `player` mode is fail-closed and strips `hidden` entities before anything is drawn. Where they met, the guarantee ate the convenience: the `occupied` guard asked whether a connector was present in the panel's **rendered** set, which player mode had already stripped, so the cell read as empty and the far end's projection immediately drew a stair into it. **The strip removed the secret and the projection wrote it back, in the same render, one loop apart** — `chartdown render --mode player` drew ▼ cellar on the house panel and `check` said `ok`. The mirror case was silent instead of loud: `hidden` on the *far* end was **completely inert**, its player output byte-identical to the same document with the connector line removed (5186 bytes both), which is [#295](https://github.com/Nossimonov/Chartdown/issues/295)'s signature reached down another road. That matters because the double declaration — `hidden` on one end, plain on the other — **is** the spelling §8 already offers for one-sided secrecy, so the nearest correct attempt at a secret trapdoor was the thing that published it. The guard now reads the **declared** model, filtered to the panel's own level, while the projection **source** keeps reading the drawn one. The two halves read different sets deliberately: a hidden connector must project nothing anywhere (spec 01 §6, unchanged), but §8's own word for suppression is *declared*, and that is what makes each panel governed by the end declared on it. The level filter is load-bearing rather than tidy-uppable — without it a house connector at A1 makes the cellar's A1 read as occupied and an ordinary two-level map **with no secrets in it** loses its landing. **This moves rendered output**, which is the line it does not share with the entry above: over the seven-case matrix in both modes exactly two renders move, both in `player`, both the double-declaration idiom, and **GM mode does not move anywhere**. A document whose only connector is a lone `hidden` stair now renders player output byte-identical to a document with no connector at all — the secret is undetectable on the sheet, not merely undrawn. Not breaking under [ADR 0041](docs/decisions/0041-breaking-means-a-clean-document-stops-checking-clean.md): every affected document still checks clean, and a player sheet losing a trapdoor it should never have shown is the promise being kept. **No committed example moves** — all 18 corpus renders (9 map examples × both modes) are byte-identical and the corpus emits no warnings, before or after, but that is containment rather than cover: `fairwater-manor` was then the corpus's only multi-level document and neither of its connectors is `hidden`, so **no committed example can express this defect at all**. That gap is [#333](https://github.com/Nossimonov/Chartdown/issues/333). Per-landing visibility on a `to=<a>..<b>` shaft still costs the one-stair-one-id property [#112](https://github.com/Nossimonov/Chartdown/issues/112) was built for, and is left open for a proposal rather than closed badly.
- **`unreachable-room` walks a `to=` range the way the renderer does** ([#322](https://github.com/Nossimonov/Chartdown/issues/322)). Spec 06 §8 says a `to=<a>..<b>` range "declares landings on every level in the range" ([#112](https://github.com/Nossimonov/Chartdown/issues/112)), and the renderer's range-walking helper already expanded it correctly — the coherence lint's own reachability test did not. It read `to.split("..").includes(level)`, which sees only the two levels named in the string, so a shaft's **interior** landings — reachable only by walking the range, not by name — read as sealed: three or more levels, one `to=top..cellar` stair, and the middle floor's room warned `unreachable-room` in the same render that drew a landing straight into it. Two-level documents cannot show this, since a two-level range has no interior. The fix does not duplicate the range logic a second time in the lint; it shares it. The renderer's helper — pure, taking only a level list and a `to=` value — moved out of the renderer's own module into the shared utility module both it and the lint suite already import, so the two now call one function instead of agreeing by accident (the renderer already imports from the lint module, so the reverse import would have been circular). Not breaking under [ADR 0041](docs/decisions/0041-breaking-means-a-clean-document-stops-checking-clean.md): every affected document still checks clean, and a false positive going silent is not a legal document starting to error. **No committed example moves** — no document in `examples/` uses a `to=` range or a `through=` at all, so the corpus cannot express this class either way; a new test (three levels, a room reachable only through the range) carries the regression coverage instead.
- **A connector's annotation names the nearest landing of its own flight** ([#321](https://github.com/Nossimonov/Chartdown/issues/321), [ADR 0048](docs/decisions/0048-an-annotation-names-the-nearest-landing-of-its-own-flight.md)). The third defect on the §8 path the two entries above walk, and the one that had been sitting in plain sight: `renderConnector` computed the right value, commented at length on why it mattered, and then printed a different variable. `shown` was dead code. Spec 06 §8 has said since [#112](https://github.com/Nossimonov/Chartdown/issues/112) that the annotation names the **next landing in the direction of travel, not the far end** — so a three-level shaft `stairs shaft : A1 to=top..bot` drew **`▼ top..bot`** on its own panel, a raw range expression that names no level at all, and `▲ top` on the bottom panel, which is precisely the far end §8 forbids. **There were two defects here, not one, and the issue only saw the first.** The declaring panel printed the raw `to=` because the value was passed through verbatim; the **reciprocal** panels were wrong for an unrelated reason, being handed `source.level` as their destination, so every projected landing announced **the level the stair was written on** rather than anything about the flight. Printing `shown` — the fix the issue itself proposed — repairs neither the reciprocal panels nor, worse, the `through=` case, where it turns `▼ top..bot` into `▼ mid` and so names a level spec 06 §8 gives **no landing at all**: a wrong answer replaced by a plausible one. The annotation is now derived from the **flight** rather than from the panel that drew it. A flight's landings are every level its `to=` names, **plus the level it is declared on**, **minus every level its `through=` names**, and each panel names whichever of those is nearest it in `levels:` order — with an interior panel equidistant from a landing above and below naming the one above, which §8 now states rather than leaving to iteration order. **Two-level documents cannot show any of this**, because one hop makes the next landing and the far end the same level; that is why it survived #112 and why the project's one test for it, asserting `/[▲▼] (top|low)/` on a panel served by the reciprocal path, passed on the broken renderer and the fixed one alike. Not breaking under [ADR 0041](docs/decisions/0041-breaking-means-a-clean-document-stops-checking-clean.md): no document's diagnostics change, every affected document still checks clean, and what moves is an annotation that was stating a falsehood. **No committed example moves** — all 18 corpus renders (9 map examples × both modes) are byte-identical and the corpus emits no warnings, before or after — but this is containment and not cover, and more starkly than for #319: `fairwater-manor` was then the corpus's only multi-level document and **no committed example uses a `to=` range or a `through=` at all**, so nothing in `examples/` can express this defect in any form. That gap is [#333](https://github.com/Nossimonov/Chartdown/issues/333). Drawing **both** annotations on an interior panel, which a panel with two genuine next landings arguably wants, is left to a proposal rather than widened into a bug fix.
- **An ambient a map never shows is reported, not redrawn** ([#290](https://github.com/Nossimonov/Chartdown/issues/290), [ADR 0050](docs/decisions/0050-a-pool-that-fills-its-field-is-reported-not-redrawn.md)). The fourth and last of the defects that came out of spec 04 §5's silence about how far a field reaches, and the only one [ADR 0042](docs/decisions/0042-a-field-is-drawn-on-the-map-field-of-its-own-panel.md) left open on purpose. A `3x3` battlemap at `5ft` is a **15ft room**; a `lantern : B2 light=60ft` in it reaches `r=384` against a 96px field, so the hole cut for the pool swallows the wash whole and a document opening `light : dark` renders with **no darkness anywhere on it** — `check` reporting `ok` throughout. The render is **faithful**, which is why nothing about it changes: a 60ft lamp does light a 15ft room, an emitter is a pool of its range cut into the wash ([#106](https://github.com/Nossimonov/Chartdown/issues/106)), and `60ft ÷ 5ft × 32 = 384` is simply correct. The fault was never in the drawing. **The document declares two things that cannot both show, and the renderer picked one silently.** So it now WARNS, naming the emitter and its declared range on the emitter's own line rather than on the `light:` header — `'lantern' reaches 60ft, which covers the whole map field` — because a map with three lamps on it needs to be told which one out-ranges the room. This is the ruling spec 04 §5 already made one bullet earlier for [#287](https://github.com/Nossimonov/Chartdown/issues/287), applied to the case it did not cover, so it is the same answer rather than a new one; the report is per **panel**, since a level is a different place and a lamp filling the cellar says nothing about the floor above. The mechanism was that `fieldHoles` carries **markup** — the holes are already SVG strings by the time the wash is assembled, and a string cannot be asked whether it covers a rect — so a parallel record of the *shapes* now rides alongside and the field is sampled against it; union-of-shapes against a rect has no closed form the renderer can afford under [ADR 0007](docs/decisions/0007-typescript-stack.md), and the admitted cost is that a filament of darkness thinner than the sample step goes unreported. Rejected on the way: **softening the hole** so a dark map keeps a floor of residual darkness, which is the most direct reading of the issue's own wording and loses because it contradicts the settled hole-in-the-wash model, moves every render of every map declaring an ambient, and re-opens [#263](https://github.com/Nossimonov/Chartdown/issues/263)'s inversion; and **clipping the hole to the field**, which is what the issue asked for first and was measured a **no-op** — `maskUnits="userSpaceOnUse"` with the field rect already makes SVG discard mask content outside it, so the change would be real bytes and zero pixels. Not breaking under [ADR 0041](docs/decisions/0041-breaking-means-a-clean-document-stops-checking-clean.md): a warning is not an error, `check` still exits `0`, and every affected document still checks clean — the same clause [#287](https://github.com/Nossimonov/Chartdown/issues/287) shipped under when it added a warning to a `light:` header. **Nothing drawn moves**, which is the property the decision rests on: all 18 corpus renders (9 map examples × both modes) are byte-identical and the corpus emits no warnings, before or after — and no committed example newly reports, because none declares an ambient at all. Its decision record spent eleven days parked outside the sequence at `9999` after `preview` took its original `0045`, and took **0050** on revival rather than the apparently-free 0048, which [#321](https://github.com/Nossimonov/Chartdown/issues/321) held unmerged; PR #337 has since merged it. What is **not** fixed here is the sibling found while fixing it: a pool and its own cut-out disagree under `occluded=none`, filed as [#327](https://github.com/Nossimonov/Chartdown/issues/327) and deliberately left, since unifying them would move renders inside a change whose whole claim is that it moves none.

## [0.6.0] — 2026-08-08

### Changed

- **BREAKING — the hex ledger form is checked like the grouped form** ([#277](https://github.com/Nossimonov/Chartdown/issues/277), [#280](https://github.com/Nossimonov/Chartdown/issues/280)). `grammar.ebnf` calls them two spellings of one thing — *"grouped alternative: ordinary line form"* — and every check added since was taught to one of them, so three ledger blind spots were found one at a time. Swept against the entity path, four checks differed and three were missing outright: a **bare archetype word** was refused as a type word on an entity line and silently drawn as generic terrain on a ledger (`C2..C4 terrain`), an **unknown `key=`** went unreported where `taepr=0.3` warns everywhere else, and an **out-of-set facet value** went unchecked. All three now run on both spellings, on the terrain word and on every content word. An **edge or corner in the address slot** used to fall through to the terrain slot and report as a malformed line, naming neither the token nor the fix; it now names itself and the hex to write instead — and suppresses the malformed catch-all, so one mistake is reported once. The fourth difference is **deliberate and written down**: a bare word after the terrain word is a CONTENT word by grammar, where the same word on an entity line is a flag, so there is no flag to check against `states=` and an unknown content word stays legal (spec 04 §3). Breaking under [ADR 0041](docs/decisions/0041-breaking-means-a-clean-document-stops-checking-clean.md): ledger lines that checked clean now error. `brenmark` is untouched.
- **BREAKING — an address form nothing can consume is refused, not quietly reread** ([#281](https://github.com/Nossimonov/Chartdown/issues/281), [ADR 0043](docs/decisions/0043-an-address-form-a-slot-cannot-consume-is-refused.md)). Spec 02 §5 makes edges and corners addressable and gives the job only to the edge — *"walls, doors, and windows live on cell edges"* — and the renderer answered the rest by accident, silently, in two directions. `edgeSegment` switched on `n`/`s`/`w` and returned the east edge from `default:`, so `"e"` was served by the fallthrough and **all four corners rode along with it**: a door at `C3.nw` opened on the far wall of its room, and a freestanding `wall : C3.nw` drew the same segment as `C3.e`. Meanwhile a feature, token or terrain on an edge was looked at by no placement path at all, so `statue s1 : C3.n` **rendered byte-identically to a document without the line**. Now: a corner is an error wherever written, naming the four directions that work; an edge is an error on anything but a barrier, an opening (including one in unbuilt geometry) or a structure detail naming one, and the message hands over the cell to write instead. The address form is **reserved, not removed** — a proposal may still give corners a meaning, and refusing now makes that a decision rather than a discovery. `edgeSegment` names `e` explicitly, so the next direction added to spec 02 §5 fails at the door instead of becoming an east edge. Breaking under [ADR 0041](docs/decisions/0041-breaking-means-a-clean-document-stops-checking-clean.md): documents that checked clean now error — though each was already getting a map that contradicted it. No committed example moves.
- **BREAKING — a structure detail says one of three things, or is refused** ([#293](https://github.com/Nossimonov/Chartdown/issues/293), [#294](https://github.com/Nossimonov/Chartdown/issues/294)). Spec 06 §3 makes the slot a closed set — a wall state, an opening, or a barrier word, with side words or edge tokens for a predicate — and neither half was enforced. A **cell** predicate hit a bare `continue`: `stairs : at A1` under a room rendered byte-identically to its own absence with `check` reporting `ok`, and so did `door : at A1`, the archetype the slot exists for. A subject outside the three drew a line in **the wall's own ink at the wall's own weight** — `#3d3629` at 3, the exact stroke the wall on that edge already drew — so it was invisible and it was the wrong mark; that is the else-branch [#103](https://github.com/Nossimonov/Chartdown/issues/103) fixed the routing into and left live. A **barrier** subject fared worse still, drawing there *and* on its own themed run, so a `fence` edge came out twice at two different weights. All three are now errors naming a spelling that works — an opening on a cell is told to name its edge, and anything that belongs in the room is told to take its own line (`stairs : on cellar at A1`), which is the form [#292](https://github.com/Nossimonov/Chartdown/issues/292) proposes to replace. A wall state is recognised by the parent's **declared states** rather than by matching the literal `ruined`, so a state on a derived structure word works too. Breaking under [ADR 0041](docs/decisions/0041-breaking-means-a-clean-document-stops-checking-clean.md): a document that used to check clean now errors. No committed example moves.
- **BREAKING — an archetype name is grammar, and using one as a type word is now an ERROR** (#266, [ADR 0039](docs/decisions/0039-an-archetype-name-is-grammar-not-a-type-word.md)). The nine names in spec 04 §1 were never vocabulary *entries* — only ever the target of a binding — so `archetypeOf` returned `null` for them and the word fell through to §3's inference as though it were undefined. In a structure detail that drew **the inverse of the line**: with `arch : opening sight=all` declared, `arch : at A1.w` cut the wall and `opening : at A1.w sight=all` **added** one, two lines naming the same archetype and the same facet at the same edge. Nothing was reported, and the reachability lint made it worse by counting the `arch` line — so the `opening` line's inertness only surfaced when the `arch` line was deleted and a document that had been "working" started warning about a room nothing can reach. The nine are now legal in exactly one position, the right-hand side of a vocabulary binding, and reserved in every type-word position: entity lines, structure details, and a `[vocab]` entry's own left-hand side, that last one so a document cannot shadow its way back to the old behaviour. The error names a fix that can be pasted (`'[vocab] arch : opening'`). This narrows "unknown words never fail", which always governed words the language has no opinion about and never the nine it is made of; an archetype has no theme subject either, since §4's fallback chain ends at "generic shape + the word as label". **No existing document moves** — nothing in `examples/`, `docs/` or the standard library used a bare archetype word. A refused entity no longer also orphans its detail lines, so one cause reports once — and *only* that one message is suppressed: a detail beneath a refused parent is still checked for what it says about itself, so an author is not told about the parent on one run and the child on the next.

### Added

- **A map in a note can be zoomed and panned** ([#186](https://github.com/Nossimonov/Chartdown/issues/186)). The Obsidian plugin drew a map once at the note's column width and offered no way closer — inline SVG does not get Obsidian's image zoom — so every feature whose correctness is a matter of scale was unreadable at the one scale on offer. **Ctrl/⌘ + scroll** zooms about the cursor, dragging pans a zoomed map, and the toolbar gains **+ / − / Fit**. A bare wheel still scrolls the note past the map, rather than trapping it. The reader's position survives a re-render, so a mode toggle or an edit to a `.cd` file does not throw them back to the whole map. Zooming moves the **`viewBox`** rather than scaling the element, which is the operation that makes detail emerge: measured for #186, `non-scaling-stroke` holds 2px across a 4× change in rendered width, so scaling magnifies geometry and stroke together and reveals nothing, while narrowing the viewBox grows the geometry and leaves the strokes. The arithmetic is now shared with the playground rather than written twice.
- **A `via` control may be a cell** ([#258](https://github.com/Nossimonov/Chartdown/issues/258)). A grid map writes every other position as `D8`, and had no way to shape a course but a world-unit pair — in units that document never uses. `stream : from fountain via D8 to sink-hole` bends the course through that cell, and renders identically to the `path` spelling through the same three cells. A gridless point on a grid map is **reported, not rounded**: cell size follows `scale:`, so the same `(60,40)` would name a different square after a `scale:` edit and the number in the document would stop being the shape on the map. A cell on a gridless map is reported for the mirror reason.

### Fixed

- **An ambient baseline says so when a map kind cannot draw it** ([#287](https://github.com/Nossimonov/Chartdown/issues/287)). `light: dark` on a `region` or `hexcrawl` rendered **byte-identically to its own absence** with `check` reporting `ok` — `ambientWash()` existed only in `battlemap.ts` and nothing said the header had been understood and dropped. The answer is not to wash those map kinds: at region and hexcrawl zoom a reader is above the weather, and whether a place is dark enough to matter is a **tactical** question — the same reasoning that keeps `difficult` off a region map. So spec 04 §5 now says an ambient baseline is a battlemap concern, and unlike `difficult` — which says nothing at all — this **warns**: an author who writes `light: dark` is picturing a dark sheet, and silence lets them keep picturing it. The line still parses and the map still renders; nothing about the document is wrong, only unanswerable at that scale. The message names the affordance that does work on every map kind — the regional override, `light "The Sunwell" : blob at (140,120) size=70mi daylight`, which is how a stretch of cavern open to the sun is written. That override has a defect of its own, filed as [#305](https://github.com/Nossimonov/Chartdown/issues/305).
- **A field's regional override draws its state** ([#305](https://github.com/Nossimonov/Chartdown/issues/305)). Spec 04 §5 promises each affordance takes its fill *"from the theme's `<field>` / `<field>.<state>` entry"*, and the state half was never asked for: every region entity resolved through `terrainFill(chain)` with no context, so `light "The Sunwell" : blob … dark` and the same line saying `daylight` emitted the **identical polygon** — the base `light` fill, fully opaque, with the theme's declared weights reaching nothing. A lightless stretch of cavern and a sunlit one were one mark. Each of the four `light` states now draws as declared: `dark` at `#10131a`/0.86, `dim` at `#1b2029`/0.55, `moonlight` at `#1d2740`/0.45, `daylight` at `#ffd98a`/0.20. Scoped to **fields**: the same lookup serves every region entity, and widening it would change how any state on any word draws, which is [#206](https://github.com/Nossimonov/Chartdown/issues/206)'s question rather than this one. Shipped with [#287](https://github.com/Nossimonov/Chartdown/issues/287) deliberately — that change documents an ambient baseline as a battlemap concern and sends region authors to this affordance, so it had to be able to tell sunlight from pitch dark.
- **A theme can repaint the whole sheet, furniture included** ([#286](https://github.com/Nossimonov/Chartdown/issues/286)). [#150](https://github.com/Nossimonov/Chartdown/issues/150) wired the `ink` surface into entity drawing and stopped at the entities: the document title, the level caption, the compass and the scale bar kept the bare constant, so `ink : fill=` was a declaration the renderer's **own dead-declaration lint** ([#116](https://github.com/Nossimonov/Chartdown/issues/116)) reported as reaching nothing — correctly, with the gap underneath it. Spec 08 §2 lists `ink` in the closed surface set and exempts no part of the sheet. The **coordinate letters were worse**: they carried a literal `#8a8272`, not even the constant, so no lever of any kind reached the letters a GM calls out in play — and a fallback could not have fixed them, since the default theme declares `ink` and a surface lookup never reaches its fallback. They are ink drawn *quietly*, and the output now says so: the old literal is ink at **60% over paper** (0.590/0.602/0.622 solved per channel), so the subduing survives as an opacity while the colour comes from the surface. Four committed examples move by that treatment and nothing else — every non-`<text>` element is byte-identical.
- **The audit gate runs on the path that publishes** ([#253](https://github.com/Nossimonov/Chartdown/issues/253)). CI's `audit` job triggers on push-to-branch and pull_request, and a tag push is neither — so the one moment code left for a registry was the one moment nothing checked it. On the morning of the 0.5.0 tag, three advisories landed against shipped transitives of `@chartdown/mcp`, one a high-severity SSRF, and they surfaced only because an unrelated PR went red; a few hours later and `v0.5.0` would have published them with every check in the release workflow green. The release now audits at the same threshold CI uses, before it builds or tests, and a failing audit stops the publish. Deliberately no override flag: the escape hatch for an advisory with no fix is a pull request that pins the dependency or documents the exception, so it stays visible in git rather than in an input someone sets while trying to ship ([ADR 0029](docs/decisions/0029-a-shipped-dependency-is-ours-to-answer-for.md)).
- **A field's drawing stops at the map field of its own panel** ([#284](https://github.com/Nossimonov/Chartdown/issues/284), [#288](https://github.com/Nossimonov/Chartdown/issues/288), [#285](https://github.com/Nossimonov/Chartdown/issues/285), [#289](https://github.com/Nossimonov/Chartdown/issues/289), [#291](https://github.com/Nossimonov/Chartdown/issues/291), [ADR 0042](docs/decisions/0042-a-field-is-drawn-on-the-map-field-of-its-own-panel.md)). Spec 04 §5 fixed the shape of everything a field draws and said nothing about where the paper ends, so the wash, the emitter pool, the pool's cut-out and the level panel each acquired a different boundary. On a `3x3` battlemap — a 144×144 page whose field is (24,24)–(120,120) — the wash covered the margins, drawing the document's own title at **1.06:1** contrast and painting the coordinate letters out completely; a `light=120ft` torch drew an `r=768` pool with no clip of any kind; that same circle masked out every pixel of the wash; and level panels carried no clip at all, so a lamp declared `level=cellar` lit the ground floor above it. All four now stop at the field — the margin band is the **paper**, not the place, and it carries the apparatus for reading the map. Only the drawing is bounded: an emitter's declared range is world data and still exports at its true value. What a hole *means* inside the field is a separate question and stays open on [#290](https://github.com/Nossimonov/Chartdown/issues/290).
- **A hidden structure detail stays off the players' sheet** ([#295](https://github.com/Nossimonov/Chartdown/issues/295)). Spec 01 §6 makes `hidden` legal on **any content line** and player mode **fail-closed**, but the strip read only the entity — so `door : at B2.s hidden`, written one indent in as a structure detail, drew the secret door on the player render **byte-identically to a door nobody was hiding**, and `check` said `ok`. The same secret written outdented as `door : on cellar at B2.s hidden` was withheld correctly, so the slot the line was written in decided whether a secret was kept — and the failure was silent at every point a GM could have caught it, up to and including handing the sheet to the table. Details are now stripped in player mode beside their entity. Stripped in the model rather than the parser, so the AST keeps saying what the document said and the mode stays the renderer's question. Not breaking under [ADR 0041](docs/decisions/0041-breaking-means-a-clean-document-stops-checking-clean.md): every affected document still checks clean, and a player render losing a door it should never have had is the promise being kept rather than broken.
- **`light: daylight` reads as daylight** ([#263](https://github.com/Nossimonov/Chartdown/issues/263)). It was the one ambient state with no theme entry, so the base `light` fill — which exists for emitter pools — answered the lookup and the missing opacity fell through to a default written for darkness. The brightest condition a map could declare rendered at **0.82**, heavier than `dim` (0.55) or `moonlight` (0.45), washing black walls brown and all but hiding the grid. It also inverted what the map said about its own light: an emitter's pool is a hole cut in the wash, so a campfire became the brightest thing on a sunlit map. Now declared at **0.20** — a warm cast on the paper rather than a filter over it — and a declared tone with no declared weight is **reported**, so the next word added to a field's closed set cannot inherit a darkness default in silence.
- **A battlemap course keeps its shape** ([#259](https://github.com/Nossimonov/Chartdown/issues/259)). #238 resolved `from … to …` in cell space using the two endpoint refs and **dropped everything else** — the `via` controls and each endpoint's `at` refinement — with a code comment where a diagnostic belonged. The course drew as a straight line the document had not asked for, byte-identical whatever shape was written: #239's failure one level down, where the placement resolves and its payload vanishes. Controls the grid can site now shape the course; the rest is reported.
- **A `[labels]` override moves the label on every map kind** (#252). An author-placed override was parsed, resolved against its entity, and validated fail-loud — a typo'd subject is a hard error — and then **discarded** by the battlemap and hexcrawl renderers. Every signal an author got said the line had taken effect, which inverts spec 07 §5's one absolute: *"author-placed `[labels]` overrides are never omitted."* `labelOverrides` was read twice in `region.ts` and **zero times** in the other two. All four hints now work in cell and hex space: `at`, a compass word, `sprawl`, and `along`. A hexcrawl went further and implemented no part of `[labels]` at all, so it could not carry free text either, though spec 07 §2 calls the section universal — it can now, and a hint a hexcrawl cannot site is reported rather than dropped.
- **A display name may hug the colon** (#251). `forest "Dark Wood": blob …` was rejected as having no predicate, and the error named the whole line rather than the missing space. The header-style split refuses any chunk containing a quote — right for `gm="a: b"`, wrong here — so the chunk fell through to the string branch, whose trailing-quote strip cannot match a chunk ending in a colon: the name became `Dark Wood":` and no colon token was emitted. An attached colon is legal everywhere else in the language, and this bit hardest in `[labels]`, where an override's subject **is** a bare quoted name, so `"The Black Altar": at …` was the natural thing to type and the exact shape that failed.
- **An emitter spends the field word it names** (#268). `reportDeadVocab` collected spent words from header keys and values, derivation bases and type words, but never from entity **pair keys** — so a field used exactly as spec 04 §5 says to use it was reported dead: `[vocab] silence : field` with `bell b1 : D4 silence=30ft` warned that `silence` "is declared here and never used", when the declaration is precisely what gives the pair meaning. The advice was unfollowable too, since the only way to stop carrying the word was to delete the declaration the emitter depends on. The comment above the header loop shows the case was half-considered: it credits `light: dim`, the ambient baseline, and missed the emitter — the affordance the `field` archetype exists for. The shipped `light` never exposed it, being a stdlib word where only a document's own `[vocab]` is checked ([ADR 0022](docs/decisions/0022-a-declaration-is-a-promise.md)). Credit is restricted to keys naming a declared **field**, resolved through the derivation chain so a derived field counts, and so a document declaring a word that merely collides with a reserved parameter (`[vocab] size : feature`) is not held to be using it by every line carrying `size=`. A genuine dead declaration — the `mountian : terrain` typo the check exists for — still warns.
- **An archetype's facets now reach a word that states no default** (#267). Spec 04 §2 grants a word "a facet its **archetype** gives it whether or not the word states a default", and only the `morph=` half of that clause was implemented — consumable keys came from *declared* facets alone. A word bound straight to an archetype has nothing above it in the chain to inherit from, so `[vocab] hatch : opening` followed by `hatch : at A1.w sight=all` warned that `sight=` was not a parameter `hatch` could use, citing the very section that grants it, and dropped the pair. The standard library hid it — `door` and `window` declare `passes=`/`sight=` themselves — but not on its own barriers: `pillar : barrier` declares neither facet and could take neither, and `fence : barrier sight=all` could not take `passes=`. Spec 04 §1's table is now encoded as `ARCHETYPE_FACETS` and unioned into the consumable set, so `passes=`/`sight=` reach barriers and openings, `occluded=` reaches fields, and the rest of the table lands where §1 puts it. The check is otherwise unchanged: a key no word, archetype or field can consume still warns.

## [0.5.0] — 2026-08-02

Three of these came from one reader's afternoon with the language — a friend of the maintainer who wrote a battlemap, named its terrain, and reported what it did instead. Between them they moved a spec rule that had been decided against on purpose.

**Read the first item before updating a pipeline.** A document that `check` accepted may now be rejected, and that is deliberate.

### Changed

- **BREAKING — a hexcrawl reports a relational placement it cannot site, too** (#248). The same class as the item below, one grid short: `hexcrawl.ts` branched on address/range with no trailing `else`, so `realm second : near duchy` drew nothing and said nothing — measured, a valid hex range added 1178 bytes to the render where the relational spelling added 34, all of it a legend entry. Now `at <hex>` **is** the bare address (§7 makes `at` optional on grids and a hexcrawl is one), and every other form is reported, naming the spellings a hexcrawl actually has rather than a battlemap's. What those forms should *resolve* across hexes is deliberately unanswered — a proposal apiece, as the same questions were for the battlemap. **Region maps were checked and are unaffected.**
- **BREAKING — a relational placement a battlemap cannot site is now an ERROR, where it used to be silence** (#239, #238). Six of spec 02 §7's nine forms — `near`, `<measure> <compass> of`, `<compass> edge of`, a bare `on <ref>`, a lone `along`, and `from … to …`/`join` — rendered **byte-identically to the same document with the line deleted**, with no diagnostic, across every archetype. §7 is normative for all map kinds, so this was non-conformance rather than an unimplemented extra, and it is the failure spec 06 §6 already ruled on for `area` on a feature (#207): *"silence is the one answer that is certainly wrong."* It was found twice, one form at a time, before it was recognised as a class. Now: `at <cell>` is the bare cell (§7 makes `at` optional on grids, so the two spellings cannot differ); **`from <ref> to <ref>` and `from <ref> join <ref>` draw a course** in cell space per [ADR 0038](docs/decisions/0038-a-placement-form-means-the-same-thing-on-every-map-kind.md), so a stream between two ponds moves when either pond does; and every form that states a relation without stating a square is **reported**, per §7's own ambiguity rule, naming the cell-bearing spelling to use instead. Resolution happens once in the model, so the renderer, the lints, the wall collector and the UVTT exporter cannot disagree. New example: [undercellar](examples/undercellar/).

- **BREAKING — spec 06 §6's "extent is always declared, never derived" is reversed** ([ADR 0038](docs/decisions/0038-a-placement-form-means-the-same-thing-on-every-map-kind.md), #231): `forest dark-wood "Dark Wood" : north of babbling-brook` places terrain on the far side of another entity's course, and means on a grid what the same form has always meant on a region map. This **reverses** spec 06 §6's "extent is always declared, never derived", which rejected a fill-to-the-river mechanic — on the grounds that one production in a closed grammar meaning something on one map kind and nothing on the other was the larger defect. The objection it protected against turned on the word *silently*, and `north of babbling-brook` is the version that says so in the line; the four hand-tiled ranges it replaces are the version where a wood's dependence on a river is invisible. Ink and coverage are answered separately, as they already are for a path band (#145): the fill runs to the reference's **centerline** — a `width=1` band inks 85% of its cell, so a fill stopping where its cells stop would leave a 2.4px hairline of paper down the reference's whole length — while a cell is covered when its **centre** lies strictly beyond the course, which sends ties to the reference. Not exempt from `terrain-crosses-wall`: that report is what makes a derived extent auditable when its reference is edited. Scoped narrowly — §3's `open` flag and §5's level surfaces stay declared.

- **Every named battlemap river, road, wood and marsh now carries a label, so existing maps redraw** (#232). A named river, road, wood or marsh rendered its geometry and no label at all — while features, structures, tokens and staging zones on the same map labelled correctly, and the same terrain on a *region* map did too. Spec 06 §7 already required it twice ("visible text labels are reserved for display names…", and "line-feature labels (all scales): a path's label anchors at the arc-length midpoint of the rendered course"), and spec 07 §5 ranks these labels first in claim order — a priority rule for a label that was never drawn. The tooltip rule covers the fallback *word* of an unnamed entity, so `forest : area A11..F15` still labels nothing. A course's name rides its course and **slides along it** when the midpoint is crowded rather than stepping off; an area's name sits within its footprint, dodging the pieces it renders beneath. `redford-crossing` and `fairwater-manor` gain their river and road names.

- **The toolchain moves to TypeScript 7** (#227), held back from the dependency batch in #226 because it reported one error the repo could not resolve. The error was real but misattributed: TS 7.0.2 blames the *enclosing* expression for an always-nullish operand nested inside it, so `TS2871: This expression is always nullish` named an expression that can return a string — and the obvious response, deleting the named expression, deletes working code. What it was pointing at, two levels down, was a dead `note` arm in the region point-label fallback: free text returns earlier in the loop and `continue`s, so nothing with `note` in its chain ever reached it. A mutation test proved it dead against the whole suite and every example. The arm also matched the literal type word, which [ADR 0016](docs/decisions/0016-derivation-carries-word-keyed-behaviour.md) calls non-conforming — a word *deriving* from `note` would have missed it and grown a marker beside its caption, which spec 07 §2 forbids. No rendered output changes.

### Fixed

- **A crossing takes its colours from the theme** (#208). The three colours a ford and a bridge draw with were literals at the draw site, so `ford : fill=` in a theme reached nothing — including the built-in theme's own `ford : fill=#cfd4b8`, which had been dead since it was written. **A default ford therefore changes colour**, from the hardcoded `#c2d4dc` to the pale stony `#cfd4b8` the theme has been asking for all along; it reads further from the river it interrupts, which is the point of a crossing. Resolution walks the derivation chain, so `stepping-stones : ford` inherits `ford`'s styling ([ADR 0016](docs/decisions/0016-derivation-carries-word-keyed-behaviour.md)) — but stops **at** the crossing word rather than falling through to `feature`, whose generic tint is not a ford. A bridge with no theme is unchanged to the byte.
- **`terrain-crosses-wall` names the structure, its line, and where the terrain leaves it** (#234). It named none of the three, so a map with several crossings emitted byte-identical warnings at one line number and a reader could not tell which building was which. It matters more under a relational extent ([ADR 0038](docs/decisions/0038-a-placement-form-means-the-same-thing-on-every-map-kind.md)): that ADR answers §6's "silently track another's edits" objection by pointing at this lint, so the audit path has to be readable. The edges were already computed to check them against openings, and thrown away.
- **A course label reads left to right whatever direction its course was declared in** (#232 follow-up). Text on a path runs the path's way, so a watercourse written east-to-west drew its name mirrored. The author's declaration order says where the water starts, not which way the letters go.

### Added

- **A region free-text caption is pinned by test** (#227). Every previous `note` case was a battlemap, so the region path had no coverage — which is how the dead arm above survived. The new case covers a bare `note` and a word derived from it, and asserts the *absence of a marker* rather than the presence of the text: a caption that falls through to the point branch still puts its words on the map, just beside the marker that spec 07 §2 promises is not there.

## [0.4.0] — 2026-07-29

The largest release so far, and the one with the most reasoning behind it: 22 ADRs, from [ADR 0016](docs/decisions/0016-derivation-carries-word-keyed-behaviour.md) to [ADR 0037](docs/decisions/0037-geometry-is-in-map-units-ink-is-in-canvas-units.md).

Two bodies of work dominate. **Placed morphology** (#93) gives coasts and rivers discrete, nameable, promotable features — a cape becomes a thing a story can attach to rather than a wiggle in a line. And **eleven rounds of authoring against a real coastline** — Puget Sound, traced from imagery — found the failures no unit test was going to. Most of the Fixed section is that work, and its shape is consistent enough to state as a rule: *the bug is almost never a crash. It is a document that says something true and a map that quietly says something else, with `check` silent because nothing is invalid.*

### Changed

- **BREAKING — a staging zone has one spelling** ([ADR 0015](docs/decisions/0015-one-staging-zone-spelling.md), #121): the word `start` (or anything deriving from it) with an area placement — `start party : J14..L15`. Spec 06 §4's inference rule ("a token-archetype word with an area placement renders as a staging zone") is removed, and a token word carrying an area is now a fail-loud error naming both fixes. Previously the same picture came from two spellings with **different theme subjects**: in `party start : …` the type word is `party`, so `start : fill=` styled nothing — a trap that caught a reader of that very section. The three example lines migrate; the rendered zone label changes from `start` to `party`. Because it breaks, this ships in 0.4, never a patch.
- **BREAKING — a battlemap feature placed with a drawn shape is an error** (#207). `pit p : area D4..F6` used to render byte-identical to a document with no pit in it: no mark, no label, no diagnostic. A feature's footprint on a battlemap is cells — a cell or a range — and `area`/`blob`/`path`/`ridge` are terrain's forms. The refusal names the word and gives both spellings that work. On a **region** map an `area` on a feature is a declared outline ([ADR 0026](docs/decisions/0026-shape-is-declared-data.md)) and is unaffected.
- **BREAKING — `chartdown-measure coast --fill` defaults to 0** (#199, [ADR 0036](docs/decisions/0036-a-measurement-reports-what-it-removed.md)). The old default of 2 removes every channel narrower than *four* miles, and Admiralty Inlet's narrowest is 3.02mi — so it deleted Puget Sound while reporting a plausible control count. A closing acts at each channel's narrowest place rather than its median, and on a real coast the two populations interleave: no radius is safe. Every run now states what share of the water it consumed.
- **Every coastline moves by half its stroke width** ([ADR 0034](docs/decisions/0034-a-border-lies-on-one-side-of-its-line.md), #185). A stroke centred on a boundary puts half its ink on each side, and *which* half is not a question the model can answer — so where two shores approach, the two water-side halves meet and fill the passage between them. `bank=` (`land`/`water`/`both`) says which side the ink lies on, and each stroke is clipped to the region that owns it. There is deliberately **no spelling for a centred stroke**. The default is `land`, decided by arithmetic rather than by convention.
- **Every organically-finished outline moves, and stops depending on `extent:`** ([ADR 0037](docs/decisions/0037-geometry-is-in-map-units-ink-is-in-canvas-units.md), #203). The texture applied to a declared outline carried its thresholds in *canvas* units, so the same document drew a different shape on a wider sheet: measured, an island's centroid moved 0.16mi between a 100mi and a 350mi extent, closing a declared 0.1mi channel and making `check` report a welded island on a document clean at the other size. The rule now: **anything that decides where the land is is in map units; anything that is ink laid on top is in canvas units.** The finishing itself — shaped `area` outlines that still read as drawn rather than surveyed — arrived in #96.
- **Recalibrated `reach=` against real coastlines** (#161), and **a bite's profile is no longer locked to its depth** (#158) — a constant head-width is non-conforming, since it left `taper=` choosing only *where* the neck fell and a fjord still came out a spearpoint.
- **Render resolution is an author choice**, not a fixed canvas ([ADR 0020](docs/decisions/0020-render-resolution-is-editorial.md), #139): `detail: overview|reference`.
- **Water wins every overlap** (#98): terrain of every kind is clipped to the land side of the water it meets, so a range reaching the sea no longer floats on it.
- **Closed header value sets are validated** (#135) and **malformed header formats fail loud** (#136) — a map built on a silently-defaulted header is a map built on something nobody wrote.
- **An out-of-set `passes=` falls to the vocabulary default**, not to `closed` (#131).
- **A path's ends reach the edges of its terminal cells** (#145): a band drawn only to the cell centre stopped halfway through the square it was declared to occupy, and authors bent documents around it — Fairwater Manor's King's Road ran a cell *inside* the gatehouse so the two would meet.

### Added

- **Placed morphology** (#93, [ADR 0023](docs/decisions/0023-detail-is-data-not-noise.md)): `cape headland peninsula spit` · `bay cove sound fjord` · `island islet atoll oxbow`, placed with the existing `on <ref> at <point>` / `near <ref>` forms — no new placement grammar. `reach=` gives a word its proportions, `taper=` how far its sides converge — and on a *detached* feature `reach=` is elongation instead, since an island has one dial where a jut or bite has two (#159). Geometry is a pure function of (kind, anchor, size), independent of `seed:` and of every other entity, and **promotion is geometry-stable**: adding an id never moves the shape ([ADR 0025](docs/decisions/0025-a-blob-declares-an-extent-not-an-outline.md)).
- **A feature declares its own line** ([ADR 0026](docs/decisions/0026-shape-is-declared-data.md), [ADR 0030](docs/decisions/0030-a-centerline-carries-its-own-width.md), [ADR 0033](docs/decisions/0033-width-is-a-cross-section.md)): a jut or bite may state its centerline with `via`, each control carrying the channel's width there — `via (46,64)@1.5mi`. That width is normatively the **cross-section square to the centerline**, because the term admits readings differing by more than half again on the same water. A detached feature may carry its outline instead, framed as offsets from its anchor so moving it stays one coordinate.
- **A detached feature takes its bearing from the water it sits in** ([ADR 0024](docs/decisions/0024-a-feature-takes-its-bearing-from-the-water-it-sits-in.md)) — which is what lets land divide water with no placement form of its own.
- **An enclosed sea declares its side by shape** (#157); **a named stretch of water is a name, not a mass** (#160).
- **A narrow channel is drawn as a symbol** ([ADR 0035](docs/decisions/0035-a-channel-too-narrow-to-see-is-drawn-as-a-symbol.md), #185): below a legibility floor expressed in viewport units, the gap between two land regions is stroked in the water's own colour, so a sub-pixel passage reads at map scale and converges to its true width as the map is given more room. The land never moves.
- **`@chartdown/measure`** ([ADR 0028](docs/decisions/0028-measurement-is-an-optional-package-in-typescript.md), [ADR 0032](docs/decisions/0032-a-measurement-emits-a-line-that-draws.md)): four verbs — `inspect`, `feature`, `coast` (#198), `island` (#197) — turning georeferenced imagery into declarations, **emitting a line the renderer will accept and checking it the way the renderer will**. Zero runtime dependencies ([ADR 0029](docs/decisions/0029-a-shipped-dependency-is-ours-to-answer-for.md)), and it reports what it consumed rather than only what it produced ([ADR 0036](docs/decisions/0036-a-measurement-reports-what-it-removed.md)).
- **A second theme that travels** (#74): `ink-and-vellum.theme.cd`, keyed entirely on standard-library words, restyles every example unaided; per-example overlays `use:` it for document-specific vocabulary. Written to be inherited rather than selected, which is what keeps the dead-declaration lint honest about it.
- **Coherence lints** (#123): six warning-level checks over resolved geometry — `door-onto-void`, `structure-unsupported`, `unreachable-room`, `dangling-connector`, `overlapping-structures`, `terrain-crosses-wall`.
- **Dead-declaration warnings** ([ADR 0022](docs/decisions/0022-a-declaration-is-a-promise.md), #116, #148, #149): a theme or vocabulary declaration matching nothing now says so — including a `glyph=` naming a glyph no `[glyphs]` section defines, which liveness alone cannot see.
- **Sub-maps** ([ADR 0021](docs/decisions/0021-a-map-is-the-sum-of-its-files.md), #109, #143, #144): anchored `detail=` and the `inset:` child half, validated in both directions.
- **Shafts** (#112) · **repeated placement** (`every`, #114, #140) · **a barrier word on a structure side** ([ADR 0017](docs/decisions/0017-openings-perforate-terrain.md), #130) · **a shape anchored to a feature** (#142) · **`join` for confluences** (#94) · **solitary `peak` and `volcano`** (#95).
- **Terrain kinds** ([ADR 0013](docs/decisions/0013-terrain-kinds-aspect-adaptation.md), #82) and **realm edges that follow features** ([ADR 0012](docs/decisions/0012-borders-are-relationships.md), #81).
- **Fields generalize light** ([ADR 0018](docs/decisions/0018-fields-generalize-light.md)): ambient conditions are content, and the vacant `light` archetype becomes `field`.
- **Label legibility**: a scale-aware floor (#132), leader lines and rotation before omission (#133), line labels claiming before point labels ([ADR 0019](docs/decisions/0019-line-labels-claim-before-point-labels.md)).
- **Every declared state is drawn, or the reason it is not is written down** (#206): `door` locked/barred/stuck/ruined, `pit` difficult, `volcano` erupting. `volcano.dormant` and region-scale `difficult` deliberately draw nothing, and the spec now records why.
- **Derivation carries word-keyed behaviour** ([ADR 0016](docs/decisions/0016-derivation-carries-word-keyed-behaviour.md)), **appearance zones and surfaces** (#150), **UVTT export in the playground** (#86), **Obsidian's Copy/Paste Chartdown round trip** (#88), **one-command version bumps** (#90), and **a multi-continent stress-test example** (#73).

### Fixed

Almost all of one kind: **the map was plausible and wrong.**

- **An island welded to the mainland is reported** ([ADR 0027](docs/decisions/0027-an-island-is-separate-or-it-is-a-peninsula.md), #180). An island still mostly *in* water but touching the shore is joined by the land union, and the document's island is not one on the map. The test is navigational — if a body of water large enough to impede navigation exists, the map has to show it. Reported, never repaired: inventing water nobody declared is the same failure as quietly resizing a feature.
- **A feature's water side was one global vector** (#178), wrong on any shore that wraps a peninsula — measured, a bay drew eight miles out into open sea on the western limb. It resolves locally now, and an undetermined side is **reported rather than guessed**; an anchor on its host's own centerline is refused rather than picked by a coin flip ([ADR 0031](docs/decisions/0031-a-bank-the-document-did-not-choose.md), #191). The same rule had refused centerlines and arms outright under an enclosed sea (#175).
- **Unevenly spaced `via` controls folded a centerline at any size** (#189): a uniform spline gives every span an equal share of the parameter however long it is. Centripetal knots make how *many* controls state a line stop changing the line — a guarantee rather than a tuning.
- **A refusal names which of five causes** (#183, #194, #156): fold, off-end, overlap, off-normal, pinch. Each has a different fix, and reporting one as another sends an author to edit the wrong thing. What refuses a bend is its **radius against the half-width**, never its cumulative turn (#177) — a circle of any radius accumulates 360°.
- **A bent centerline drew a cusp that `check` passed** (#176): two vertices closer than the output's own precision print as one point, and a zero-length segment has no direction — so a smooth 29° curve measured 155.9°. The check was right and the output was lying.
- **An arm was refused when an unrelated feature was added elsewhere on its host** (#179): a second pass re-spaced a curve that was already finished. A feature's shape must not depend on what else the map contains.
- **Measurements landed in the wrong frame** (#196): coordinates came out relative to the image's own corner and nothing said so, so a declaration measured against imagery and pasted into a document whose extent starts elsewhere landed seven miles from the water — a valid feature at the coordinates it states.
- **`inspect` did not disclose a rotation it was applying** (#202): gated at 1°, it stayed silent at 0.39°, which moves the corners of a 135mi frame by 0.57mi. It now reports the rotation in miles, each landmark's own residual, and the fitted transform, so nobody has to reconstruct it.
- **`feature` accepted a mouth that named the whole sea** (#200), and **`island`'s diagnostics could not be followed** (#201) — a suggested point that reproduced its own message, land of 0 sq mi, and no way to tell a misplaced anchor from a genuinely welded island.
- **A measured centerline wandered into the arms and was drawn tighter than it was checked** (#192) — the renderer and the measurement now spline it the same way, from one shared implementation, because two copies is how a measurement comes to check a line the renderer never draws.
- **An unknown `key=` pair was accepted in silence** (#195); **`reach=` on an entity line was ignored** (#153).
- **Placed morphology drew nothing on a `from…to` course with no `via` points** (#154), and **the fold refusal measured sampling density rather than geometry** (#155).
- **Line features reserved a corridor for their whole length** (#134); **line labels sat on their course but not where it read as theirs** (#137); two lint false positives — terrain wholly inside a room (#146) and a door onto a road (#147).
- **A barrier word in a structure detail rendered nothing** (#128); **structure perimeters ignored the theme** (#117).
- **`<title>` tooltips embedded user text unescaped** (#79) — an `&` in a display name broke the SVG.
- **The Action cleaned up orphaned SVGs by inference** rather than by provenance marker ([ADR 0014](docs/decisions/0014-provenance-gated-cleanup.md), #78).
- **The digest's header-key list was incomplete** (#99), and is now locked to `KNOWN_HEADER_KEYS` by a test.

## [0.3.3] — 2026-07-25

Mostly the conformance half of the #93–#115 batch review: everywhere the implementation didn't do what the spec already said. Found by two authoring-at-scale exercises — a Middle-earth region map and a full-Moria eight-level mega-dungeon — plus the release-plumbing and co-authoring work from the same cycle.

### Fixed

- **One vocabulary chain, walked once.** A derivation living in a `use:`-imported library did not inherit its base word's theme entry, though the identical derivation written in an in-document `[vocab]` did — the renderer rebuilt its vocabulary table from the AST, which carried only the document's own entries. The document now carries its imported vocabulary, so themes resolve through spec 04 §2's one shadowing order. This defeated exactly the configuration spec 04 §2 calls "the shareable/publishable surface," and it failed silently. (#101)
- **Derived openings are openings.** Opening appearance was matched against the literal words `door`/`gate`/`window`, so `portal : door` — or anything bound straight to the `opening` archetype — fell through to a fallback that drew it *in the wall's own ink, at the wall's own weight, on top of the wall*. Every non-stdlib door was invisible; a Moria map with 88 archways rendered as unbroken stone. Appearance now resolves through the vocabulary chain and openings are recognized by archetype. (#103)
- **Walls gap at openings.** A structure's perimeter was drawn straight across its openings with the door mark painted over it, so the render disagreed with spec 06 §9's normative UVTT export, which subtracts every opening edge. An arch is a hole, and now draws as one. (#103)
- **Four archetypes ignored the theme entirely.** `opening`, `barrier`, `path`, and `zone` draw code carried hardcoded colours and never consulted `[theme]` — `wall`, `door`, and `pillar`, the interop-critical triad of spec 06 §2, could not be restyled at all. The built-in values now live in the default theme document like every other palette entry (no privileged styling path), and all nine archetypes resolve through one lookup. (#105)
- **Free text renders as text alone.** A `note` drew a generic feature marker beside its text at point placements, so every caption asserted there was a thing at that spot. Spec 07 §2 already said its "rendering *is* its text"; it now is, at every placement form, with `sprawl` letter-spaced so it differs from a bare range. A placement the renderer draws nothing for now warns instead of vanishing silently. Spec 07 §2 states the no-marker rule normatively and points authors at named entities for the pin case. (#104, #107)
- **Water wins every overlap.** Massifs and terrain patches painted *over* the sea, so a range meeting the coast floated on open water and a gulf could not cut one named range in two. Terrain of every kind is now clipped to the land side; islands stay land above their sea. Spec 05 §2's guarantee is generalized from zonal terrain to terrain generally. (#98)
- **Structure perimeters are theme subjects.** Room outlines — the most visually defining element on a battlemap — were drawn in literal ink at a literal weight by a path that consulted no theme at all, so a theme could restyle the paper, terrain, props, doors and freestanding walls and then outline every room in the same brown. They now take `stroke=`, `width=` and `dash=` from the structure's own word, through derivation and `word.state`. Found re-testing 0.3.3 at a call site the #105 reproduction never reached. (#117)
- **A bare `ruined` ruins every side.** `ruined` is a declared state of `building` (spec 06 §2), but structures honoured it only as a detail line selecting sides (`ruined : north`) — the flag form drew intact walls, while freestanding barriers had always honoured it. (found alongside #117)
- **`glyph=` and `fill=` compose.** A themed glyph was emitted `fill="none"` with hardcoded ink, so a themer chose the shape *or* the colour, never both — spec 08 §3 lists them as independent members of one closed set. Point-placed barriers also skipped the glyph lookup entirely, so a `pillar` could not take a column symbol though every other point-placed entity could. (#119)
- **`check` surfaces render-side warnings.** The #104 diagnostic lived in the renderer, so the command authors and CI actually run still reported `ok` for a document containing a line that renders nothing. `check` now renders a map (GM mode, output discarded) and merges those diagnostics — the general rule being that every diagnostic a renderer can emit must be reachable from `check`, or authors and CI see different documents. (#120)
- **`check` validates all three document kinds.** Vocabulary and theme documents need no `map:` (spec 04 §2, spec 08 §1), but `check` validated everything against the map rules — reporting a missing `map:` and then discarding a 126-line theme as unknown sections. Two of the three kinds had no validation path, so a misspelled appearance property or a typo'd derivation base was discovered by the map looking wrong. Kind is now inferred from the sections present (the durable fix is #110's `kind:` discriminator), in the CLI and the MCP server alike. (#102)

- The spec digest — served publicly as `llms-full.txt` — and `grammar.ebnf` still titled themselves "spec draft v0.1", misinforming every LLM that bootstraps from them; the grammar also claimed sections 01–07 while covering 08. Headers now state the real version, and a core test locks both artifacts to `SPEC_VERSION` so they can never drift again. Owner-caught.
- The digest's "Header keys" list omitted `map:` (the one REQUIRED key — present in the skeleton snippet, invisible in the list an agent scans), plus `levels:` and `level:`. User-caught (#99). The list is now complete, and a core test asserts every `KNOWN_HEADER_KEYS` entry appears in it — a future header key can't ship without its digest line.
- **Releasing is one command** (#90): `npm run bump -- x.y.z` rewrites every version surface — the six package.json files, render-svg's pin on core, `SPEC_VERSION`, the digest/grammar/spec-README headers — and rolls the `[Unreleased]` changelog into the new section with compare links. The core consistency test derives the expected version from the packages and asserts *every* surface agrees, so a surface that escapes the command fails `npm test` instead of shipping (the failure mode behind both the 0.3.1 fix and the digest-header fix above). The right way is now the easy way.

### Changed

- Obsidian: each map's toolbar gains the round-trip pair (#88; replaces an unreleased primer-button design after owner review). **Copy Chartdown** leads the copied text with `;` comment lines naming the language and pointing at the public reference (`llms-full.txt`), so a paste into an LLM chat self-identifies without the plugin bundling a spec or pushing AI at anyone. **Paste Chartdown** brings a reply back: accepts bare Chartdown or a ` ```chartdown ` fence, strips a returning breadcrumb, **validates before writing** — an invalid paste changes nothing and names the offending line; the button grays out while the clipboard is empty (format metadata only — content is read exactly once, on an explicit paste click). The store README now presents the co-writing workflow and how to bootstrap an assistant (paste `llms-full.txt`, or `@chartdown/mcp` for tool-using agents).

## [0.3.0] — 2026-07-22

The region-map release, forced out line by line by [the Sundered Reach](examples/sundered-reach/) — a two-continent stress test reviewed by its owner across twenty-plus rounds until the map earned `spec-aligned` status.

### Added

- **Borders are relationships** (spec 05 §2, [ADR 0012](docs/decisions/0012-borders-are-relationships.md), #81): realm `area` boundaries may **follow features** — `along <ref>` between two vertices traces the feature's curve (a ridge, a coastline), so moving the feature moves the border. `border` leaves the path family and attaches a **state** to a stretch of one realm's boundary: blanket frontier, facing word (outward normal, eight sectors, open edges only; `inner` for bay shores), `along <ref>`, or two-realm sugar for the shared abutting stretch — most specific wins. States are open vocabulary; overlapping realm claims are legal (a disputed march); stated seams render as an atlas band with dash-dot, default boundaries the same dash-dot lighter.
- **Terrain kinds** (spec 02 §9, 03 §2, 05 §2, [ADR 0013](docs/decisions/0013-terrain-kinds-aspect-adaptation.md), #82): terrain is patches (`blob`/`area`), belts (`ridge <points> width=<measure>` — a variable-width massif with peak marks, tapering to tips, merging where ranges overlap), or **zones** — climatic terrain defined by a frontier, declared as an area following the frontier and the coasts (continent-scoped) or a half-plane (map-wide). Zonal frontiers render as dotted lines in the zone's tint. `ground: <terrain-word>` names what unmarked land is. Mountain crest and extent coexist on one entity (`ridge (…) area (…)`) — refinement is additive, and references always mean the crest.
- **Aspect adaptation** (spec 03 §2, ADR 0013): a reference names the *thing*, not its geometry class — line-needing forms take the polyline else the area boundary; point-needing take point → midpoint → centroid; area-needing take polygon → belt. Never guesses between multiple meaningful lines: `along` a crestless area fails loud, disambiguated by `along <compass> edge of <ref>`.
- **Dense-map label conduct** (spec 07 §5, #73): placement claims run in priority order — author overrides, point markers (proximity IS their meaning; capitals before minor features), curve labels, area names, realm/sea sprawls — while paint stacks the reverse. Labels **shrink before migrating** (size floor, then tracking), are **omitted rather than drawn over other text**, and a split sprawl name **repeats once per clear stretch** of its water, centered and sized to the room it actually has.

### Changed

- Glyphless words tint **deterministically by their base word** (golden-angle hues, parchment-muted; theme `fill=` overrides): table and barrel — and every unknown word a scene will ever hold — stop being the same grey square, on the map and matched in the legend. (#71)
- **Nations tint by name**: every realm gets its own deterministic color (the #71 principle at entity grain), with boundary dashes to match — six nations, six tints, one glance.
- Region label placement grew a body of cartographic judgment: curve labels prefer straight stretches and the outside of bends (over-bent names set straight instead of mushing), roads dodge area names (never the reverse), mountain names sit ON their massif region-style, realm and zone names stay inside their own territory, and settlement type steps down so capitals stop rivaling the map title.

### Fixed

- Polygon seas bound by coastline curves (two continents can exist, #76); islands render as land; water→realms→terrain paint order; half-planes span the full map beyond their frontier; phantom label claim boxes; `text-anchor` always written (SVG defaults to start); diagonal label collision gaps; fitLabel prefers size over tracking.

## [0.1.0] — 2026-07-21

The first public release: the Chartdown language v0.1 and its reference implementation, published to npm as [`@chartdown/core`](https://www.npmjs.com/package/@chartdown/core), [`@chartdown/render-svg`](https://www.npmjs.com/package/@chartdown/render-svg), [`@chartdown/cli`](https://www.npmjs.com/package/@chartdown/cli), and [`@chartdown/browser`](https://www.npmjs.com/package/@chartdown/browser).

### Language

- Three map types: `battlemap` (square/hex grids), `hexcrawl` (ledger-style exploration logs), and `region` (gridless, organic finishing) — [spec 01–08](docs/spec/)
- One line grammar (`subject : predicate`), chess-style addresses on every grid, and a closed nine-form relational grammar with order-bounded, deterministic, fail-loud, live anchor resolution
- Open vocabulary over nine closed archetypes: unknown words never fail; themes own all appearance; no bestiary by design
- Battlemap depth: structure details (walls, doors, windows) with light and sight semantics; derived crossings (`ford : on river on road`); elevation with emergent ledges and `drop` fall edges; multi-level structures (`levels:`, connectors with `to=`, per-level surfaces `earth`/`air`/`roof`/`terrace`); `open` structures (walls without a ceiling); feature footprints as range placements; room-relative placement (`table : on kitchen at C2..D2`)
- The GM/player split: `hidden`, `gm=`, and `[gm]` strip fail-closed from player renders
- Themes are Chartdown documents (`[theme]`/`[glyphs]`), layered and shadowed
- Labels: `labels: names|keyed|none`, label overrides, battlemap word-labels as tooltips

### Implementation

- `@chartdown/core` — parser and AST, zero runtime dependencies
- `@chartdown/render-svg` — deterministic seeded SVG renderer (same input + seed → byte-identical output)
- `@chartdown/cli` — `chartdown render` / `chartdown check`, self-contained bundle
- `@chartdown/browser` — one script tag renders ` ```chartdown ` fenced blocks in place
- The [playground](https://nossimonov.github.io/Chartdown/) — fully client-side editing, level switcher, share links
