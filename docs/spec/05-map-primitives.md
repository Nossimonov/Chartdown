# 05 — Map Primitives

**Status: Draft** (accepted from proposal [#17](https://github.com/Nossimonov/Chartdown/issues/17) as proposed). Enumerates the shared **topographic standard library** and defines the **region** and **hexcrawl** map types: their sections, the hex ledger grammar, and exploration states. Battlemap-specific vocabulary is section 06. No new mechanisms appear here — everything below is content under specs 01–04, which is why this section carries no ADR.

## 1. The topographic standard library

The standard library is a Chartdown vocabulary document (spec 04 §2), reproduced here normatively. Renderers MUST bundle it; documents may shadow any of it. Words use their natural spoken form; tiers and variants are derivations, not parameters.

```chartdown
# Chartdown Standard Library — topographic

[vocab]
; terrain
sea : terrain
lake : terrain
plains : terrain
grassland : terrain
farmland : terrain
forest : terrain
jungle : terrain
hills : terrain
mountains : terrain
peak : terrain
volcano : peak states=dormant,erupting
marsh : terrain states=difficult
desert : terrain
dunes : desert
snowfield : terrain
tundra : terrain
wasteland : terrain

; linear features
river : path
stream : river width=1
road : path
trail : road
canal : river
pass : path
coastline : path

; crossings — features that sit on paths by relation
ford : feature states=difficult
bridge : feature

; settlements — one base word, tiers by derivation
settlement : feature
capital : settlement
city : settlement
town : settlement
village : settlement
hamlet : village

; sites
keep : feature
castle : keep
tower : feature
ruin : feature
dungeon : feature
lair : feature
camp : feature
mine : feature
shrine : feature
temple : shrine
port : feature
cave : feature
landmark : feature

; zones
realm : zone
region : zone
border : zone

; annotation (see section 07)
note : feature

; placed morphology (§4)
cape : terrain morph=jut        headland : cape     peninsula : cape    spit : cape
bay : terrain morph=bite        cove : bay          sound : bay         fjord : sound
island : terrain morph=detached islet : island      atoll : island      oxbow : terrain morph=detached
```

**A solitary mountain is a point, not a small region.** `peak` places one mountain at a position — Erebor's meaning is that it stands *alone*, which `mountains … blob size=` cannot say, because that draws a small mountainous region. `volcano : peak` is an ordinary derivation, so it inherits the point-scale placement and a theme may swap the motif exactly as `licorice-forest` swaps a forest's; absent a theme the renderer still distinguishes the two silhouettes, so the derivation reads on the map rather than only in the display name ([#95](https://github.com/Nossimonov/Chartdown/issues/95)).

The list is deliberately curated: every missing word is one `[vocab]` line away (spec 04 §3's escalation ladder), and a small library is a stable one.

## 2. Region maps

Known sections: `[water]`, `[terrain]`, `[paths]`, `[settlements]`, `[features]`, `[realms]` — plus the universal `[vocab]` and `[gm]`, and `[labels]` (section 07). Sections provide inference context (spec 04 §3) and skim structure; lines inside use the standard grammar.

**Water and coastlines.** Water bodies are ordinary terrain areas; `coastline` is an ordinary path. A water area placed with the half-plane form — `coastline coast : from …` then `sea "The Argen Sea" : west of coast` — fills the map extent on the stated side of the referenced path, clipped to it. (Per spec 03, the coastline carries an explicit id because things reference it.) There are no winding-order conventions: the sea is on whichever side the author says, which is what the line reads as.

**Terrain kinds** (ADR 0013). Terrain facts come in three geometric kinds, each with its idiom:

- **Patches** — forests, marshes, wealds: things with an outline sitting *on* the ground. `blob`/`area`, the paint-on-parchment model, unchanged.
- **Belts** — ranges following a spine with breadth: `ridge <points> width=<measure>` (spec 02 §9).
- **Zones** — climatic terrain (tundra, desert, icecap) defined by a **frontier, not an outline**. A zone scoped to one landmass declares an `area` whose edges follow the frontier and the coasts (the same feature-following as realm boundaries, ADR 0012): `tundra "The White Reach" : area (1055,205) along "The Frostline" (1505,145) along fareast (1540,0) (1020,0) along eastshore` — each continent carries its own frontier, and adding a second continent's tundra is a second declaration. The half-plane form (`north of <ref>`) remains for truly map-wide zones; note a half-plane spans the FULL map beyond its frontier, every landmass included. Either way, renderers give zonal terrain honest terrain fill — never the washed zone tint — and a non-coastline path serving as a zonal frontier renders in the frontier register (a fine dotted line in the zone's tint), not at river weight.

**Water wins every overlap.** Terrain of every kind — patches, belts, and zones alike — is clipped to the land side of the water bodies it meets: where a range reaches the sea, or a gulf bites into one, the water edge cuts it cleanly. This is a property of the map model, not of one terrain kind, and it is what lets a belt run right up to a shore without bleeding onto it, and one named range be split by a gulf without the author pre-splitting it. Islands are the converse and stay land: an island rises *above* the sea that surrounds it.

**Land is one region.** A coastline exists only where land meets *water*, so where two land shapes overlap the boundary between them is not drawn: an island touching the shore renders as one continuous coastline with the mainland, and two overlapping islands render with a single outline. Stroking each land shape's whole outline regardless of what is already land beneath it is **non-conforming** — it draws a ring lying across the peninsula, and a lens with a seam through it. At map scale this is the common case rather than an edge case: an island separated from the mainland by a channel narrower than the stroke should read as one landmass, as Bainbridge does across Rich Passage (#165). It follows that an island is also **land in every other sense**: terrain declared on one is not clipped away by the sea it sits in.

**A path band is not terrain**, so it is not clipped — a bridge, a ford and a canal all touch water on purpose, and a `river` reaching a `join` on another river is water on water by design. But a river whose **end lies inside a water body** is drawn straight across it and out the far side, and the renderer MUST report that as a **warning** naming the river and the body. It is reported rather than clipped because it is nearly always a typo rather than a claim, and because the fix is a spelling that already works, so the diagnostic can name it: `to <coastline> at (…)` or `from <coastline> at (…)`. Either end counts — rivers are commonly authored **mouth-first**, from the sea and inland, which is how nine of the Puget Sound exercise map's rivers came to start a mile or two offshore with nothing said (#166). An end declared against a reference, or by `join`, is never questioned however its curve lands.

An island whose footprint lies **wholly on land** is therefore a sentence the document can write and no map can mean, and the renderer MUST report it as a **warning** naming the island. Left unreported it draws a stroked contour on open grass with a place-name beside it, which at full-map zoom reads as a faint mark rather than as a mistake — nine of the fifteen islands on the Puget Sound exercise map were misplaced this way without a word from `check` (#164). This is the region-map form of §06 §10's door onto solid rock, and strictly easier: a geometric fact rather than an inference about intent. **An island is separate, or it is a peninsula** *([ADR 0027](../decisions/0027-an-island-is-separate-or-it-is-a-peninsula.md), [#180](https://github.com/Nossimonov/Chartdown/issues/180))* — there is no third state, and a document that declares one while the map draws the other MUST be reported. The weaker failure is the one that matters more: an island still mostly **in** water but **touching** the shore, so the union above joins the two and the document's island is not an island on the map. The test is navigational — **if a body of water large enough to impede navigation exists, the map has to show it**. Harstine Island is separated from the mainland by Pickering Passage, which boats go through; drawn welded at its southern end, the map says you cannot get from Case Inlet to Totten Inlet that way, and you can. A map that denies a passage is not functional, whatever it looks like.

Conformance is stated on the **gap**, not on the overlap: an island with any open water between it and the shore MUST NOT be reported, however narrow the channel — a sub-scale gap is still a gap, and a cartographer draws such channels wider than scale precisely to keep the map navigable. An island whose outline reaches or crosses the shore MUST be. This is a **warning**, and the renderer MUST NOT open a channel to repair it: inventing water nobody declared is the same failure as quietly resizing a feature. The author's fixes are real — widen the channel, move the island, or accept that at this scale the two are one landmass and stop calling it an island.

The report MUST state the **contact**, not the clearance, and MUST say **where** it touches and **how far** the island must move to clear it. A share of shore still surrounded by water is true and reads as reassurance — an island reported at 98% sounds clean when it means the union has already swallowed it — and without a position and a distance the author must hunt for the touching end and guess the correction, which on a long island is several edits rather than one. This is the same requirement §4 places on a refusal: a diagnostic that does not carry an actionable number sends its reader to change something at random.

**A named stretch of water is a name, not a mass** *(from proposal [#160](https://github.com/Nossimonov/Chartdown/issues/160)).* A `zone` declared in `[water]` — "Central Basin", "Admiralty Inlet" — names part of the sea it sits in rather than a body of its own. It renders as a **label and at most a faint boundary in the water's own tint, never a fill**, which is the same restraint the frontier register uses for zonal terrain. It remains an ordinary entity: an id, a `gm=`, a `detail=`, and anything may reference it. A zone on land is unaffected and keeps its realm tint.

**Named ground.** The optional region header key `ground: <terrain-word>` states what unmarked land is (`ground: plains`); the theme paints the base accordingly. Unstated, the ground is unspecified open land — the parchment.

**Mountains: crest and extent coexist; refinement is additive** (ADR 0013). `ridge (…)` declares the crest and sketches the extent (the belt). Adding `area (…)` *on the same entity* refines the extent while the crest remains — `along <ref>` always means the declared crest, so references never break under refinement. An area-only mountain entity (a plateau, a highland waste) has **no crest**: a line-needing reference to it is ambiguous and fails loud, resolved by naming a face — `along south edge of <ref>` (spec 02 §7). All political outcomes are authorable and none is a representational default: border on the divide (`along <ref>`), a no-man's march (each realm to its near face), or a whole-range claim (boundary along the far face).

**Political boundaries** (ADR 0012, superseding the original border-as-path idiom). A realm's boundary is its own geometry, and a border names a **relationship**, never a location:

- **Realm edges may follow features.** Inside an `area` point list, `along <ref>` between two vertices makes the boundary trace the referenced feature's rendered curve between the projections of those vertices (the same feature-following as `from A to B along X`, spec 02 §7): `realm valemark "Valemark" : area (110,240) along westspine (552,540) …`. One definition — moving the feature moves the border.
- **`border` attaches a state to a stretch of one realm's boundary.** Its predicate names the realm, an optional stretch selector, and a state word: `border : valemark contested` (blanket — every frontier stretch not abutting another realm), `border : valemark east contested` (facing selector), `border : valemark along westspine sealed` (feature selector), `border : valemark carrowen contested` (two-realm sugar: both realms' shared stretch, symmetric). More specific selectors win where declarations overlap: along-feature beats facing beats two-realm beats blanket. State words are ordinary vocabulary resolving through the theme chain (spec 04 §3) — unknown states render generically, never fail. `gm=` on a border annotates the relationship and is GM-only as usual.
- **Facing is per edge, by outward normal** — the direction an outsider crosses from — bucketed into eight compass sectors, ties rounded clockwise. A bare facing word selects only **open** edges (the outward-normal ray from the edge midpoint escapes without re-entering the realm); the `inner` modifier selects the complement (edges facing the realm's own land across a bay). A C-shaped realm's `north` border is its very top alone; `inner north` is the bay's south shore; the bay's back wall stays open toward the mouth it faces.
- **Overlapping realm claims are legal and meaningful** — two realms declaring the same land is a disputed march, not an authoring error; renderers blend the tints and draw both boundaries. Asymmetric states on a shared seam are likewise permitted (each side declares separately) — each realm's own boundary stroke carries its own state.

A border whose realm reference resolves to nothing, or whose named realms never abut, has nothing to style; renderers SHOULD warn and MUST NOT invent geometry for it. Realm membership by half-plane (`realm "Khar" : east of spine`) remains available.

## 3. Hexcrawl maps

Known sections: `[hexes]`, `[routes]`, `[regions]`, plus universals.

**The ledger line** (the sanctioned shorthand of spec 01 §7 / spec 02 §4):

```
<address-or-range> <terrain-word> <feature-word>* ["Display Name"] <param>*
```

The first vocabulary word is the hex's terrain; subsequent feature words are its contents; a display name attaches to the most prominent content, or to the hex itself if there are none. The grouped form (`forest : C4 D3 D4`) remains legal per spec 02 §4.

**Exploration states.** Omission = unexplored (fog/blank per theme). Two hex params refine this, both player-render concerns that GM mode ignores:

- `seen` — terrain renders, contents and labels are hidden: spotted from a ridge.
- `unexplored` — force-fog a mentioned hex, so a GM can pre-author the whole region in one document and reveal per session; the GM render shows everything.

**`[routes]`** — path-archetype words with ordered address sequences (adjacency rules per spec 02 §4). **`[regions]`** — zone-archetype words with address sets and ranges; the renderer derives the boundary.

## 4. Placed morphology

*(From proposal [#93](https://github.com/Nossimonov/Chartdown/issues/93), decided in [ADR 0023](../decisions/0023-detail-is-data-not-noise.md).)* Matching a hand-drawn coast with `via` points alone costs hundreds of coordinates, and a bare vertex is **not a nameable thing** — you cannot hang a `gm=` note or a `detail=` sub-map on "the third wiggle". Morphology words place the **discrete features** that give a coast or a river life, each a first-class entity:

```chartdown
[water]
coastline coast : from (250,20) via (150,182) (112,262) (272,322) to (250,600)
cape : on coast at (150,182) size=22mi                       ; a nameless headland — real, and pointable-at
cove : on coast at (196,300) size=15mi                       ; a landward bite
island himling "Himling" : near coast at (95,250) size=8mi   ; born named
```

- **Placement** uses the existing relational forms (spec 02 §7): `on <line> at <point>` for a feature that deforms its host, `near <line> at <point>` for a detached one. `size=` is a measure giving its extent along the host.
- **On a DETACHED feature, `reach=` is elongation.** `size=` is the long axis and `reach=` the short one as a multiple of it — the same "the other dimension" it means for juts and bites. `reach=1`, and an absent `reach=`, are a circle. The long axis is **inferred rather than declared**, because a long island in a sound parallels the water it sits in — the same ice cut both. Without this every island was a circle at its longest dimension, which is the decorative state `reach=` exists to end (#159).
- **A jut or bite may declare its CENTERLINE with `via`** *(ADR 0026, [#169](https://github.com/Nossimonov/Chartdown/issues/169))*. Without it the feature is one straight run of `size × reach`. Hood Canal runs 40mi south-west from Foulweather Bluff and then turns hard east for 15mi at **the Great Bend**, and that hook is what cuts the barb off the Kitsap Peninsula:
  ```chartdown
  fjord hood "Hood Canal" : on shore at (36,44) via (72,48) (96,92) size=3mi taper=0.15
  ```
  A dogleg is **not a branch** — one mouth, one head — so it is not the line-branching this section stages. **A control may state the channel's WIDTH there** *([ADR 0030](../decisions/0030-a-centerline-carries-its-own-width.md), [#190](https://github.com/Nossimonov/Chartdown/issues/190))* — `via (46,64)@1.5mi` — and the shape then follows that profile. That width is the channel's **cross-section square to the centerline** *([ADR 0033](../decisions/0033-width-is-a-cross-section.md), [#192](https://github.com/Nossimonov/Chartdown/issues/192))*: the distance between the two rails, measured perpendicular to the line at that control. The definition is normative because the term admits several readings that differ by more than half again on the same water, and only this one is the quantity a renderer draws — anything else makes the number in the document a different width from the channel on the map, which is the objection this section already raises against quietly resizing a feature. In particular it is **not the largest circle that fits**: that reads low wherever the line sits off-centre, since the nearer bank caps it, and high at a bend, where the circle settles into the corner and touches both outer banks at once — 1.17x the true half-width on a square elbow and more as the turn sharpens, making a channel widest exactly where it turns hardest, which is the one place an offset curve cannot afford it. Nor is it the narrowest crossing in any direction, which is the right reading at a **mouth**, where the chord *is* the opening, and finds whatever short crossing happens to lie nearby anywhere else. Without it a feature is a ribbon whose width falls monotonically from its mouth, so the opening is always the widest part; measured off imagery, Hood Canal runs 2.2, 3.9, 1.3, 5.8 and 1.1 miles across down its own length, a chain of basins joined by narrows that the ribbon misses by up to 4.04mi against a median width of 1.64. `size=` is the profile's FIRST POINT rather than a competing mechanism, a control that states no width is interpolated from its neighbours, and interpolation is EASED rather than straight — a straight one draws the basins as a row of facets, which is a surveyed polygon on a map whose first value is that a coast reads as drawn. Where widths are stated they are the shape and `taper=` governs only the generated case, the same rule ADR 0026 applies to an outline and the dials; the head then closes on the last width stated, so a channel that ends broad ends broad. A mouth narrower than the water behind it is a **narrows**, and the rails flare from it: the mouth fillet only ever CLOSES, because its square-root profile has an infinite slope at the opening — right when the channel narrows, and running it backwards sends the rail into the coast at 148°. The declared line **replaces `reach=`**, which generates one: its own length is the depth, and declaring both MUST be an **error**, because honouring either means discarding the other. It replaces its **direction** too *([#175](https://github.com/Nossimonov/Chartdown/issues/175))* — the side the feature runs to is the author's, already said by the first control they wrote, and the rule below that infers direction from the water governs only a *generated* run. Taking the side from the map here put the two in contradiction wherever the map's answer was wrong or undecidable, and the shape was then refused as a **fold the author had not written**. `size=` and `taper=` continue to give the width. The feature is drawn as a **ribbon along that line**, which makes a straight feature the two-point case of the same construction rather than a separate one. Two consequences are normative because both were measured as corners on a shape whose own curvature was never sharp: the centerline MUST leave the host **perpendicular** (the mouth's corners are pinned to the host, so a skewed departure builds the fillets in one frame with their ends in another), and sampling MUST answer to the **centerline's** curvature as well as the width profile's — a `taper=0.15` flank is nearly straight and would otherwise be sampled six times across its whole length, striding clean over the bend.
- **A jut or bite may be hosted on another one** *([#170](https://github.com/Nossimonov/Chartdown/issues/170))*. Every secondary arm of Puget Sound hangs off a primary one — Dabob and Quilcene off Hood Canal, Dyes off Sinclair. Its window is measured on **its host as its host stands**, so the arm is applied after the feature it hangs off, not alongside it: measuring both against the undeformed course would put the arm's mouth on a stretch of shoreline that is no longer there. That later pass MUST NOT re-space the curve it is given *([#179](https://github.com/Nossimonov/Chartdown/issues/179))*. Normalising a **declared** course is required (§4's window is an arc-length span), but the same treatment applied to a curve the renderer has already finished throws away outlines sampled at their own radii, and lands the new samples by total arc length — so an unrelated feature elsewhere on the coast moves where they fall, and an arm that was drawable becomes a fold. A feature's drawn shape MUST NOT depend on what else the map happens to contain. Its **water side comes from its host**, not from the map: `sea : west of hood` is not a sentence about Hood Canal, because the canal *is* water — so the side is the direction from the arm's mouth to its host's own centerline, which is ADR 0024's "ask the containing feature" asked by a bite instead of an island. The host's answer **takes precedence over the map's**, rather than filling in only where the map is silent: consulted second, the map's global guess arrives first and the host is never asked, which left one of a canal's two banks refusing every arm because that guess drove the bite inward on that side. Where that host **declares** its centerline, that line is the whole answer and the host's own water side is not consulted: requiring one anyway dropped arms whose course was already stated, making them depend on how a sea two features away happened to be spelled (#175). Declaration order is not significant. **An anchor ON the host's centerline MUST be refused** *([#191](https://github.com/Nossimonov/Chartdown/issues/191), [ADR 0031](../decisions/0031-a-bank-the-document-did-not-choose.md))*: the side is a direction *toward* that centerline, so on the line there is no direction, and the document has not said which bank the arm leaves from. This is the anchor an author reaches for — one of the host's own `via` controls, because that is the point on the canal they mean. Left unreported the bank fell to whichever of the host's two rails a vertex rounding picked: measured, the rails sat 0.752mi from the anchor apiece and answered differently, and refusals **alternated** along the canal while ignoring the feature's size entirely. A renderer MUST NOT pick — a bank chosen by sampling can be switched by an unrelated feature elsewhere on the map, which is the silent shape-change #179 forbids, and a bay that changes banks without a word is worse than one that will not draw. The report MUST name the ambiguity and give **both** banks, since naming one is the same silent pick in prose.
- **A placed feature is labelled on its BODY** *([#171](https://github.com/Nossimonov/Chartdown/issues/171))*, at the arc-length midpoint of its centerline — spec 07 §5's rule for a line feature, applied to the line this feature runs along. Its anchor is a point on the *host*, so labelling there names a 40mi canal at its mouth with forty miles of canal unnamed below it, and piles the names of several inlets sharing a stretch of coast into one spot while the water they name lies miles away. That also defeats 07 §5's crowding machinery rather than exercising it: those labels are not crowded because the map is dense, but because they were all placed at the same point.
- **A detached feature may carry its own OUTLINE** *(ADR 0026)*. `size=`/`reach=`/`taper=` are the short form and produce a lozenge — right for the anonymous mid-river islet this section is written around, and wrong for Whidbey Island, which doglegs at Coupeville. A landform a reader recognises is exactly what a campaign attaches itself to, which is ADR 0023's own test for what must be declared data, and shape was the one thing about a feature that could not be. An `area` on the entity line declares it:
  ```chartdown
  island whidbey "Whidbey Island" : near shore at (40,100) area (-2,-40) (3,-30) (1,-20) (6,-8) (5,4) (10,18) (7,32) (2,26) (-1,10) (-5,-6) (-6,-24)
  ```
  The points are **framed** — offsets from the anchor, the referent-frame rule of ADR 0009 and spec 02 §9 — so moving the feature stays one coordinate rather than a transform of the whole set, and it remains attached to its host. The outline is **organically finished** like any declared silhouette (02 §9, ADR 0025); drawn raw it reads as a surveyed polygon against every other coastline on the map. An outline **and** the dials together MUST be an **error**, because honouring either means discarding the other and a renderer that silently picks is the failure this section exists to prevent — only pairs on the *entity line* count, so a `reach=` inherited from the vocabulary is not a conflict. An outline of fewer than three points is reported. A **jut or bite** takes no outline: its shape must join its host at two points and stay joined, so it declares a **centerline** instead (staged, [#169](https://github.com/Nossimonov/Chartdown/issues/169)).
- **A detached feature takes its bearing from the water it sits in** *(ADR 0024)*. Where its anchor lies inside a `bite`, the long axis follows **that channel**; elsewhere it follows the host's local course. On an open coast the two agree, which is why the host's course served alone for so long — but inside an inlet the host is the *coastline*, whose direction runs **across** the inlet rather than along it, so an island placed in one came out as a bar damming the channel instead of an island splitting it. This is what lets an island **divide water**: Hartstene is what makes Case Inlet and Pickering Passage two inlets rather than one bay, and it needs no placement form of its own (#167). Where two channels contain the anchor the **smallest** wins, being the more specific statement about where the island is. The bearing MUST be read from the containing feature's **own declaration**, never from the rendered water: measuring the drawn sea gives the same answer, but it would make an island's shape a function of rendered geometry, so an unrelated edit to the coastline could silently re-point an island a campaign had already named — which ADR 0023 forbids.
- **`taper=` gives it a profile.** Without one every feature is a wedge — widest at the mouth, narrowing to a point — which is right for a cove and wrong for everything glacial. `taper=` says how far the sides converge on the way in, and over how much of the depth: at `1` the shape is that wedge, and as it falls the flanks run parallel for longer and the head grows broader, so the result is a trench ending in a round bight. Hood Canal, Case Inlet and Carr Inlet are near parallel-sided, and without this the only way to reach their depth was a hairline needle that read as a spine on the coast (#158). A single constant governing how much it narrows is **not** sufficient: that makes `taper=` choose only *where* the neck falls, and a fjord — whose whole character is being parallel-sided to its head — still comes out a spearpoint (#163).
- **A feature is an OUTLINE, not a displacement of the host's vertices.** Its shape is: a fillet where each flank meets the shore, so the mouth is the widest part and the corner has a radius; two flanks converging as `taper=` says; and a **rounded head**, never a point or a chord closing two parallel sides. Taking depth as a function of position along the coast instead — a raised cosine over a window, which is a *graph* — is **non-conforming**, because a graph cannot have parallel sides: reaching a fjord's depth within the width of its mouth forces the curve almost vertical, and where an almost-vertical climb turns back to horizontal its radius of curvature collapses. Measured, that radius was two hundred times finer than any sampling a renderer can afford, so every inlet drew as a polygon with 60–90° corners while passing every fold check (#163). Sampling follows the shape's own radii, so a feature is smooth at whatever scale it is drawn and costs vertices only where it actually curves.
- **Direction comes from the water, and an ENCLOSED sea says it by its shape.** A half-plane (`sea : west of coast`) describes an open ocean. Water that lies *between* two shores has no side to be on, and that is most interesting water on a continent — so a bounded body declared as an area following its coasts (`sea : area (…) along westshore (…) along eastshore`) also settles the direction, from its own extent (#157). Only the side is taken from it, so an approximate centre is exact enough.
- **`reach=` gives a word its proportions.** `size=` is the extent ALONG the host; `reach=` is how far it carries ACROSS, as a multiple of that size. It is a vocabulary facet, so derivation carries it and an author may override it per entity. Without it a word is decorative: `cove`, `sound` and `fjord` at the same size drew an identical shape and differed only in colour — useless on a coast whose whole character is that one inlet is long and narrow while another is a shallow scoop. The shipped values are calibrated against Puget Sound (#161), where measured ratios run from Point No Point at 0.33 to Hood Canal at 27: `cape` 0.55 · `bay` 1 · `peninsula` 1.6 · `cove` 3 · `spit` 5 · `sound` 6 · `fjord` 20.
- **`morph=` says what the geometry does; the word says what the thing is.** The facet is a closed set — `jut` pushes the host line away from the water, `bite` pulls it landward, `detached` draws a separate shape offset from it. The two are independent on purpose: `bay` and `cove` both bite while being water, `island` and `oxbow` are both detached while being land and water respectively, and a theme colours each by its word.
- **Direction is inferred from the host where nothing declares it.** A `jut` on a coastline goes seaward and a `bite` goes landward, resolved from which side of the line the water lies on; an author never restates what the coast already knows. This governs the **generated** run only: a declared centerline states its own direction, and an arm takes its side from the feature it hangs off. The inference is also **not** a single vector for a whole body reduced to a sign against the local normal. That is inverted on a shore that wraps a peninsula — right on one limb and backwards on the next — and where the coast turns square to it the two are perpendicular, so the side is decided by arithmetic noise rather than by the map. Where the water's declaration does not determine the side at a given anchor, a renderer MUST NOT guess silently (#175).
- **Geometry is a pure function of the placed data** — kind, anchor, size — and is independent of `seed:` and of every other entity. A feature therefore never drifts under an unrelated edit, which is the whole point of ADR 0023.
- **Promotion is geometry-stable** (spec 03). `island : near coast at (95,250) size=8mi` and `island himling "Himling" : near coast at (95,250) size=8mi` render **identically**. Naming adds a story, not a shape — otherwise a feature would move at the moment a campaign named it.
- **A feature is drawn at its declared size or reported — never quietly resized.** ADR 0023 allowed either clamping or failing loud; the spec requires **failing loud**. A clamp deliberately discards map data, and worse, it makes `size=` a lie: the same 90mi cape would come out different lengths on different stretches of coast, so the number in the document would stop determining what is on the map. Where a feature cannot be drawn as written the renderer MUST report an **error** naming the feature, its size, and its host, and leave the course undisturbed.
- **The report MUST name which of the five things went wrong**, because each has a different fix: the shape would **fold** the course back through itself (use a smaller `size=`/`reach=`, or a straighter stretch); half its mouth would lie **off the end** of the host (move it along the course); it **claims the same stretch** as another feature, which MUST also be named; its declared centerline **leaves off-normal**, where squaring the first control onto the host's normal would draw *([#183](https://github.com/Nossimonov/Chartdown/issues/183))*; or that centerline **turns tighter than the channel is wide** *([#189](https://github.com/Nossimonov/Chartdown/issues/189))*. That fourth cause is the one an author meets first, because the perpendicular the rule above requires cannot be judged by eye from a list of coordinates on a curved shore — reported as a fold it sends them to shrink an inlet that was never too big. Its report MUST give the angle, and MUST NOT quote `size=`, which is not the thing to change. A renderer determines whether squaring the first control would rescue the shape by TRYING it rather than by thresholding the angle: what angle actually bites depends on the mouth's width and the first leg's length, so a constant would be wrong on most maps. Where the trial draws, the report MUST offer that control, and it is then a fact about this map rather than an estimate. **Where it does not, the cause is still the skew** *([#194](https://github.com/Nossimonov/Chartdown/issues/194))*: a large departure is exactly the case one squared control cannot rescue, and reporting it as a fold or a pinch instead sends an author to spread `via` points through a bend they did not write — the corner is between the renderer's own mouth lead and their first control. The report MUST then give both bearings, where the centerline leaves and where the host faces, and MUST NOT offer a coordinate, because none is known to draw. A renderer knows the two apart BY POSITION rather than by angle: everything before the author's first control is the mouth and the generated lead, so a fold there cannot be the fault of any control they wrote, and one past it can. The fifth is the rule below binding on the author's **own line** rather than on the host's, and it is the one a *measured* centerline meets: measurement puts controls where curvature is high, so a cluster of them describes a turn of their own spacing's radius. Its report MUST give **where**, the radius there, and the width there — a fold is local, and on a canal stated in eight controls there is no reading the offending bend off a list of coordinates — and it too MUST NOT quote `size=`, because where a profile is declared the width that folds is not `size=` at all. Two features may not occupy one stretch of a host — overlapping mouths are a contradiction in the document, and blending them silently puts a corner between two features that are each perfectly drawable alone. Reporting any of these as another is non-conforming: a diagnostic naming the wrong cause sends an author to change something that was never wrong.
- **A course may not cross itself, and may not fold to a point.** Simplicity alone is not sufficient: a curve can come to a cusp and turn back without ever intersecting itself, which draws a spike where a bay was asked for. Both are non-conforming.
- **What refuses a bend is its RADIUS against the half-width, never its total turn** *([#177](https://github.com/Nossimonov/Chartdown/issues/177))*. An offset curve folds where the centerline's radius of curvature drops below half the ribbon's width, which is a **local** condition; cumulative heading change is not a proxy for it, since a circle of any radius accumulates 360°. A bound on the total is non-conforming: it refuses a bend of many times the half-width for the same total as a hairpin, and it closes the one technique the geometry itself suggests — completing a tight corner as a series of gentler angles separated by distance, which is how a waterway of finite width turns and how a draughtsman draws one. An oxbow is most of a full circle.
- **How many controls state a centerline MUST NOT change its shape** *([#189](https://github.com/Nossimonov/Chartdown/issues/189))*. This is the rule §4 already places on a declared **host** course — where adding collinear points to a straight coast doubled the deepest drawable feature until the course was normalised (#154, #155) — asked of the feature's own line. It binds on the **spline's parameterisation**: a Catmull-Rom parameterised uniformly gives every span an equal share of the parameter however long it is, so a short span beside a long one is traversed at a wildly different speed and the curve bulges past the short one to make up the difference. Measured on a canal traced from imagery — three controls within a mile at a bend, then a ten-mile run — that bulge put **one self-crossing and a 54.9° kink** in a line the author had written as smooth, so the shape was refused at every size from 1.56mi down to 0.3mi while the same shape in two evenly spread controls drew at full size. The fold was real; the refusal was honest; the cause was the parameterisation. Spacing the knots by chord length (**centripetal**) is sufficient and is a guarantee rather than a tuning — such a spline cannot cusp or self-intersect within a span — and it costs nothing where controls are already even, since equal chords make equal knots and that *is* the uniform spline. A tool that measures a feature MUST NOT have to space its controls evenly to make its own output drawable: that thinning deletes exactly the controls a bend is made of, and on Hood Canal it refused above 1.2mi where the unthinned line drew at 2.2.
- **The drawn output MUST carry the shape that was checked.** A renderer prints coordinates at finite precision, and two vertices closer together than it can express become the same point — a zero-length segment, which has no direction, so anything reading the drawn curve measures an arbitrary angle there. Emitting one is non-conforming: it makes a curve that passed every check above appear to violate it, and no reader can tell that apart from a real cusp. Sampling finer than the output can express buys nothing and costs exactly this (#176).
- **The bite is one direction, not an offset of the curve.** A feature displaces its window along a single direction — the host's normal at the anchor. Offsetting each point along its own local normal is *not* conforming: on a headland the two arms have normals pointing well apart, so the halves of the feature travel differently and pinch the course between them, and a bay a cartographer would happily draw becomes undrawable.

Spec 02 §9's noise-free spline is **affirmed, not revised**: the connecting curve stays a smooth spline through the declared controls, and this is a discrete layer on top of it. The complementary case is [#96](https://github.com/Nossimonov/Chartdown/issues/96)'s organic finishing of terrain area outlines — a wood's edge is *texture*, which may be generated; a cape is a *feature*, which may not. That boundary is why organic finishing is refused for `[water]` and for `along`-following outlines (§2).

**Staged, not omitted:** line-*branching* morphology — `delta`, `fork` (the inverse of `join`, [#94](https://github.com/Nossimonov/Chartdown/issues/94)), and cut-off meanders — is a different geometric problem from deforming a single spine and is deliberately not specified here. Those words are not in the standard library yet, so a document using one gets spec 04 §3's unknown-word treatment rather than a silently inert declaration.

## 5. Cross-cutting

- `difficult` is a terrain/feature flag with archetype-level meaning (movement cost), carried into VTT export.
- Crossings compose with paths by relation (`ford : on "The Redford" at K9`) or direct placement at battlemap scale — there is no crossing archetype.
