# Chartdown Digest — spec v0.6

*Single-file language reference for machine/agent ingestion (issue #12). Informative — the prose sections 01–07 are normative. Maintained in the same commit as any spec change. Companion: [grammar.ebnf](grammar.ebnf).*

Chartdown is a plain-text language for TTRPG maps. A document is a standalone `.cd` file **or** a ` ```chartdown ` fenced block in Markdown — byte-identical content rules.

## Document skeleton

```chartdown
# Title                       ; optional, first line only. ";" = comment anywhere.
map: battlemap                ; REQUIRED first header line: battlemap | hexcrawl | region
grid: square 20x15            ; battlemap/hexcrawl. Hex form: hex 8x9 pointy odd-row
scale: 5ft                    ; real size of one cell (grid maps)
[terrain]                     ; [sections] group content; section determines line grammar
mud : area H11..J11 difficult
```

Header keys: `map:` (REQUIRED, always the first header line: `battlemap` | `hexcrawl` | `region`; experimental types carry a `-beta` suffix) · `kind:` (`vocabulary`|`theme` — the first header line of a NON-map document; a map is spelled by `map:`, and a document declares one or the other, never both) · `chartdown:` (spec version pin) · `id:` (doc slug for anchors) · `grid:` · `scale:` · `extent: 900x600mi` (gridless size; `<w>x<h>` + optional unit, no space) · `detail: overview|reference` (gridless RENDER RESOLUTION — `reference` doubles the canvas so fine names survive for a reader who zooms, at the cost of smaller text when the whole map is shown; default `overview`; warns on grid maps, ADR 0020) · `seed:` (int; varies deterministic organic rendering) · `levels: top base` (battlemap floor stack, spec 06 §8) · `level:` (the default floor to render) · `use:` (import vocabulary doc; repeatable) · `theme:` (suggestion only) · `labels: names|keyed|none` · `legend: on|off` · `scale-bar: on|off` · `compass: on|off` · `numbers: on|off` (these five plus `map:`/`kind:` are CLOSED SETS: an out-of-set value is an ERROR, not a silent default — `legend: yes` used to turn the legend off in silence). FORMATS are checked the same way and for the same reason: `extent:`/`seed:`/`scale:`/`chartdown:` ERROR on a malformed value rather than falling back to 800x600 / 0 / 5 / unpinned — a map silently built on a default breaks when the assumed grammar is later implemented (#136) · `inset: <doc> at <entity>` (this document is a WINDOW onto that entity of that document — the child half of the sub-map seam; the pair is validated in both directions and any disagreement is an error naming both files, #143/ADR 0021) · `ground: <terrain-word>` (region: names what unmarked land is) · **`light:`** (ambient light level — `dark`|`dim`|`daylight`|`moonlight`|any word; `light <level>:` scopes it to one panel. Absent it nothing changes; with it a `light=` emitter reads as a pool in the dark). Unknown keys/sections warn; `[x-*]` sections are silently ignored (extension namespace).

## The one line grammar

`subject : predicate` — subject = `[type-word] [id-words] ["Display Name"]`; predicate = placements, bare words (flags/vocab), `"strings"` (text), `key=value` pairs. **No parentheses in the language.** Flags: bare words (`hidden`, `difficult`, `overturned`, `ruined`, `nolabel`, `seen`, `unexplored`, `drop`, `open`). Params: `key=value` (`width=2`, `facing=south`, `light=20ft`, `size=2x2`, `elevation=15ft`, `side=party`, `gm="text"`, `link=path`, `detail=map.cd` (+ `detail-at=<parent-cell>`: anchors the sub-map's A1 in the parent grid, making the seam CHECKABLE — non-integer magnification and an under-covering child grid both fail loud naming both files; `detail=` alone stays a pointer; sub-map sources are supplied by the caller like `use:` libraries, and an unsupplied one reports UNCHECKED rather than passing, #109), `key=3`).

## Positions (spec 02)

- **Cells, all grids**: chess-style `K11`, `C4` (columns A..Z, AA…; 1-indexed; row 1 = north). Ranges `A11..F15` (rect / hex run / hex block). Lists: `C12 E13`.
- **Edges/corners**: `O6.s` (n/e/s/w), `K5.nw` (corners). Wall runs: `wall : K5.e K6.e K7.e`. **An edge places a WALL, DOOR or WINDOW and nothing else** — a barrier, an opening (incl. unbuilt geometry), or a structure detail naming one; on any other archetype it ERRORS naming the cell form (02 §5, ADR 0043, #281). **NOTHING consumes a corner yet** and writing one is an ERROR — the form is reserved for a future proposal, not removed. Both used to be silent: a feature on an edge rendered byte-identically to its own absence, and all four corners collapsed onto the EAST edge, so a door at `C3.nw` opened on the far wall. `edgeSegment` now names `e` rather than reaching it through `default:`, which is how four tokens became a fifth.
- **Gridless points**: `(x,y)` in extent units from NW origin; point ranges `(x1,y1)..(x2,y2)`.
- **Repeated placement** (02 §9): `every <n> in <range>` / `every <n>x<m> in <range>` — one entity per stepped cell, offsets from the range's NW corner so the first cell always lands (`every 4 in A1..A9` = A1 A5 A9). A QUALIFIER, not a relational form; expands at parse time, so local frames compose (`on hall at every 4 in C4..AB60` moves with the hall) and determinism is trivial. >4096 cells = error. `every <measure> along <ref>` spaces down a course by MEASURE (not a count): walks the CELLS the course covers on a grid map (`path B4 Z4` spans 25 cells, not 2) and arc length on a gridless one; expands to ordinary placements like the `in` form.
- **Framed shapes** (02 §9): `<shape> on <ref> at (dx,dy) (dx,dy)` — points are OFFSETS from the referent, so the WHOLE shape travels with it (spurs off a peak, an outwork on a keep). §7's local frame reaching shapes, which previously took literals only and detached silently. Anchoring one point instead of the frame DEFORMS the shape and is not the design. Offsets are Cartesian: interconvertible with bearing+range, so nothing is unreachable (#142).
- **Shapes** (renderer finishes organically, deterministically — finishing is not inventing; give major paths generous `via` points): `area <cells|points|range>` (TERRAIN outlines are ORGANICALLY FINISHED — the points are a silhouette, splined + roughened, so a shaped wood reads hand-drawn; `raw` opts back into literal edges; water areas and any outline with `along` spans stay literal, the latter because those segments ARE a feature's finished curve, #96) · `path <seq> width=N` · `blob <center> size=<measure>` (a DECLARED EXTENT, not an outline — ADR 0025, #173: a round mass measuring EXACTLY size= across; the finishing is TEXTURE the renderer owns and nothing may reference, and MUST be a pure function of the WORD and the EXTENT — not the `seed:`, not the id/name, not the position, not the ordinal among siblings. It was 14 points of jitter keyed on all four, so naming a blob reshaped it, an unrelated `seed:` reshaped every blob, swapping two lines swapped two islands' outlines, and three `size=40mi` blobs measured 42.5/42.0/41.6mi — which 05 §4 already forbids in terms. FINISHING MAY NEVER DECIDE AN EXTENT: where it perturbs a boundary the declared measure MUST survive. Hence `seed:` re-rolls only what declared no dimensions — an `area`'s roughening — and an all-extent document renders identically under every seed. Twins are the honest consequence of two identical declarations (ADR 0023's trade); an elongated mass is `ridge`/`area`/a detached feature) · `ridge <seq> width=<measure>` (an elongated MASS along a spine — `width=` is its breadth; the belt is the footprint, not the centerline; `ridge (…) area (…)` on one entity refines the extent while the crest survives for references).
- **Finishing may not depend on the rendered scale** (02 §9, ADR 0037, #203): a drawn shape is a pure function of its DECLARATION, and `extent:` is not part of it — it says how much world the sheet covers, not what is on it. So texture, and every threshold governing it, MUST be in MAP units or a fraction of the SHAPE, never a fraction of the canvas; a renderer whose finishing carries a canvas constant is NON-CONFORMING. Measured: the same document at 100mi and 350mi drew an island's centroid 0.16mi apart with a bbox 1.3% larger, enough to close a declared 0.1mi channel and make `check` report a welded island (05 §2) on a document clean at the other extent — while the declared coastline beside it was bit-identical, which is both the proof it is achievable and why it went unnoticed. Binds COHERENCE CHECKS too: whether two landmasses touch cannot depend on how big the picture is printed. Not restated in MILES either — the corpus runs 12mi to 1600mi, where the old 8-unit gate is 0.12mi and 15.61mi, and no distance serves a 133x spread; shape-relative is the model `organicMass` already uses (ADR 0025). The one legitimate absolute floor is the output's own precision (#176). THE CONVERSE IS EQUALLY NORMATIVE and is why this is a SPLIT rather than a blanket rule: **ink is in canvas units** — stroke widths, font sizes, marker radii and 05 §2's legibility floor are symbols whose job is legibility at the drawn size, and in map units they would be invisible on a large map and overwhelming on a small one. Anything that decides WHERE THE LAND IS is in map units; anything that is INK LAID ON TOP is in canvas units
- **Aspect adaptation** (03): a reference names the THING, not its geometry class — point-needing forms take point→line midpoint→centroid; line-needing (`along`, endpoints) take polyline (a range's crest)→area boundary (rivers stop at shores); area-needing take polygon→a ridge's belt. Never guesses between multiple meaningful lines: `along` a crestless AREA fails loud; disambiguate with a face — `along south edge of <ref>`. Terrain kinds (05): patches (blob/area), belts (ridge), ZONES — climatic terrain by frontier. Continent-scoped: an `area` whose edges follow the frontier + the coasts (`tundra "The White Reach" : area (…) along "The Frostline" … along eastshore`) — each landmass its own frontier. Map-wide: half-plane (`north of <ref>`; spans the FULL map beyond the frontier). Honest fill; frontier paths render dotted in the zone's tint, never river weight. **Water wins EVERY overlap**: terrain of every kind is clipped to the land side of the water it meets (a range stops at the shore; a gulf cuts a range) — islands are the converse and stay land above their sea.
- **Relational placement — closed grammar, only these nine forms**:
  `at (x,y)` · `70mi north of <ref>` · `east of <ref>` (half-plane) · `on <ref>` · `on <ref> at <point|local>` · `south edge of <ref>` · `near <ref|point>` · `from <ep> via (p) (p) to <ep>` (a `via` CONTROL is a point or — ON A GRID — a CELL, `via D8` #258; a gridless point on a grid map is REPORTED not rounded, since cell size follows `scale:` and the number would stop meaning the shape) · `from <ep> via (p) join <river-ref>` (CONFLUENCE: ends on the trunk's finished curve at the nearest point, LIVE so moving the trunk moves it; takes the course itself, no `at`. `to <river>` still means its MIDPOINT per aspect adaptation — the pair is deliberate, #94; two rivers that CROSS without a declared meeting — `join`, or one starting `from` the other — WARN with both names and the position, since water does not flow over water; roads are exempt, a road over a river is a ford/bridge per 06 §6) · `along <ref>`. Endpoints: ref, point, or `ref at (point)`.
- **Referent-frame `at` payloads (#34)**: `on kitchen at C2..D2` — a cell/range/edge after `at` is LOCAL to the referent (structure footprint frame, NW cell = A1; moving the structure moves its contents). A path's frame is the document grid (= the crossing chooser). Detail lines use `at`-prefixed placements for the implicit parent frame: `door : at E2.e`. Absolute placement stays legal everywhere — author's choice per line, never a mode; renderers surface the resolved absolute address (tooltips). Outside-footprint local, frameless referent, or cross-level referent = error.
- **`key=<n>` works outside `labels: keyed`** (07 §3): a pinned entity shows its number while the rest keep their names — *a map WITH a key* (a numbered route through a named map, the shape of most published modules), as opposed to *a map in key mode*, which renumbers everything.
- **Resolution rules**: references only to *earlier* declarations (forward ref = error); deterministic (document+seed); fail-loud (no room / ambiguous = error — renderers never relocate others); anchors are **live** (moving an anchor moves dependents; use a remnant landmark — `ruin "Former site of X"` — when destroying one); output is **well-formed XML** for every valid document, whatever characters user text contains.

## Identity & links (spec 03)

- Id = explicit id word(s), else slug of display name; neither = anonymous (renderable, unreferenceable). Explicit-id collisions: parse error.
- References: bare word = id lookup; `"quoted"` = display-name lookup; miss/ambiguity = error (fix: add explicit id).
- Anchors exported as `cd-<doc-id>-<entity-id>`; display-name anchors change on rename (like Markdown headings); explicit ids are stable. `link=` = entity's prose/URL; `detail=` = entity detailed by another Chartdown doc.
- `[gm]` lines: resolving subject = attachment (adds GM notes; placements forbidden); non-resolving + placement = new GM entity; non-resolving + no placement = error. `player` render mode is default and strips `[gm]`, `gm=`, `hidden`.

## Vocabulary (spec 04) — the language knows no nouns

- Nine closed archetypes: `terrain path feature structure barrier opening token zone field` (facets: `passes=`, `sight=` on barrier/opening; `size=`,`side=` on token; `occluded=` on field — `light` is the shipped field, not an archetype, per ADR 0018).
- **An archetype name is GRAMMAR, not a type word** (04 §1, ADR 0039, #266): the nine are legal ONLY on the right of a vocab-line, and are RESERVED in the type-word slot — entity line, structure detail, and a `[vocab]` entry's own left-hand side. Writing one is an ERROR naming the fix (`'opening' is an archetype … declare a word for it ('[vocab] arch : opening')`), NOT an inference. This is the one exception to "unknown words never fail" below: that promise covers words the language has no opinion about, never the nine it is made of. It used to resolve to `null` and fall through to inference, so `opening : at A1.w` in a structure drew a WALL — the exact inverse of the line — and checked clean. An archetype also has no theme subject: 04 §4's chain ends at "generic shape + the word as label", so a bare one could only render as its own name.
- `[vocab]` entries: `word : archetype [facets]` or **derive** `word : other-word [overrides]` (`licorice-forest : forest` — forest semantics, theme swaps the motif). Sources shadow in order: standard library < `use:` files < document.
- **Derivation carries word-keyed behaviour** (04 §2, ADR 0016): where a spec section attaches behaviour to a specific stdlib word — `earth`/`air`/`void`/`roof`/`terrace` (level surfaces), `start` (staging zone), `note` (free text), `light` — that behaviour is INHERITED through derivation, exactly as archetype and facets are. A word deriving from `air` is unfloored; from `note` is free text. Matching these on the literal word is non-conforming. Spec 04 §2 carries the registry of load-bearing words.
- **States SHOULD be declared** (04 §2): a bare word that is not a reserved flag should match a `states=` declaration on the word or an ancestor; an unmatched one still renders but WARNS (typo protection). Only defined vocabulary is checked; wall-state details (`ruined : north east`) and `border` predicates are exempt grammar. Stdlib: `door : … states=locked,barred,stuck,ruined` (inherited by `gate`).
- **An unknown `key=` warns** (04 §2, #195): the sibling of the states rule, closing the sharper half of the same hole — a typo in a VALUE is caught by §1's closed sets, a typo in a KEY was read, discarded and never mentioned, so `taepr=0.3` lost the taper and drew a wedge where a parallel-sided inlet was asked for and checked clean. Still no effect; WARNS naming key, word and line. What a word can consume is RESOLVED not listed (no static set fits an open vocabulary): reserved parameters usable anywhere (01 §5) · a facet the word declares OR INHERITS by derivation · a facet its ARCHETYPE gives it whether or not the word states a default (`reach=`/`taper=` belong to placed morphology as such — `bay` takes a `taper=` it does not declare, `island` a `reach=` meaning elongation) · the name of a declared FIELD (04 §5 derives that namespace from the vocabulary). Exempt: undefined words (nothing to compare against, 04 §3) and `border` (own grammar, ADR 0012). `x-` prefix carries extension data without argument, mirroring `[x-*]` sections
- **Fields** (04 §5): `light` is the shipped one; a setting declares its own in a line — `[vocab] radiation : field occluded=none states=none,heavy,lethal`. A field word earns four affordances: emitter param (`reactor : F4 radiation=40ft`), ambient header (`radiation: heavy`, `radiation <level>:`), regional override (range + state), theme subjects (`radiation` / `radiation.heavy`). Values ARE states. `occluded=` is `sight` (default, blocked like light) or `none` (fills through matter — antimagic, radiation). The emitter-parameter namespace is derived from the vocabulary: declaring the field is what makes `<field>=` mean something. **An AMBIENT baseline is a BATTLEMAP concern** (04 §5, #287): a region or hexcrawl does not draw one — at those scales the reader is above the weather and visibility is tactical, the same reasoning that keeps `difficult` off a region map. Not an error and the map still renders, but it WARNS, because an author writing `light: dark` is picturing a dark sheet. The REGIONAL OVERRIDE works on every map kind and is how a part of a region is lit differently (`light "The Sunwell" : blob … daylight`). **Everything a field DRAWS is clipped to the map field of its own panel** (04 §5, ADR 0042, #284/#288): the ambient wash, an emitter's pool, and the hole the pool cuts in the wash all stop at the area the grid or `extent:` occupies — the frame inset by its margin. The margin band is the PAPER, not the place, and carries the apparatus for reading the map (title, coordinate letters, compass, level caption) — a printed battlemap of a lightless cellar has no black border. Per PANEL, so a lamp on one level does not light another. Bounding the drawing costs no fact: the declared range exports at its true value (ADR 0037's split, one storey up). It used to be unbounded in four different ways — a wash over the margins at 1.06:1 contrast on the title, an `r=768` pool on a 144-wide page, that same circle masking out the whole wash, and level panels with no clip at all.
- **Unknown words never fail**: archetype inferred from shape/path phrase → section context → lone point/cell → `feature`; renders generic glyph + word as label, deterministically tinted by the word's base (theme `fill=` overrides) so distinct types stay tellable apart on map and legend. Spelling never inspected (no suffix magic).
- Themes own all appearance (assets live in themes, never map source); fallback chain ends at generic shape + label, so rendering never blocks.

## Standard library (spec 05/06, curated ~80 words)

- **Terrain**: sea lake plains grassland farmland forest jungle hills mountains **peak** (POINT-placed solitary mountain — `peak erebor "Erebor" : (1185,290)`; a blob of `mountains` is a small REGION, not one mountain) **volcano** (`: peak states=dormant,erupting`; inherits the point placement, and the renderer distinguishes the silhouette so the derivation reads on the map and not only in the display name) marsh(difficult) desert dunes snowfield tundra wasteland | battlemap: mud(difficult) sand grass snow ice(difficult) water(difficult) rubble(difficult) slope
- **Paths**: river stream road trail canal pass coastline
- **Zones**: realm region border (border = a relationship+state, never a location — see region row)
- **A declared state is DRAWN, or the reason it is not is written down** (05 §5, 06 §2, #206): a state rendering identically to its absence is the document saying something the map does not, and `check` cannot object because nothing is wrong. Drawn now: `door` locked (a keyhole punched in the paper's colour — inked in the DOOR's colour it is a brown dot on a brown door and invisible, which is how it first shipped) · barred (the bar, across and offset) · stuck (the wedge) · ruined (dashed and faded, the convention BARRIERS already use for that word, so one rule per word not one per archetype) · `pit`/feature `difficult` (the hatch reached terrain and crossings and never features) · `volcano.erupting` (a plume off the crater). DELIBERATELY NOT drawn, and that IS the written reason: `volcano.dormant` (a dormant volcano IS the resting cone; a second symbol invents a distinction the world lacks) and `difficult` on a REGION map (difficulty is tactical; a region map has no tactical layer). A STATE'S SPELLING DECIDES WHAT YOU ARE TESTING and there are four — a flag after the placement (`water : D4..F6 difficult`), a wall-state detail line (`ruined : north east`), a header key (`light: dark`), and the SECTION a word belongs to (`ford` in [terrain], not [features]); three of four first-pass "gaps" were fixture errors, each a confident IDENTICAL for a feature that works
- **Crossings/sites**: ford(difficult) bridge keep castle tower ruin dungeon lair camp mine shrine temple port cave landmark stairs ramp
- **A feature's footprint is CELLS, a drawn shape is REFUSED** (06 §2, #207): a feature takes a cell (`F6`) or a range (`D4..F6`); `area`/`blob`/`path`/`ridge` are TERRAIN's forms and a feature given one MUST be an ERROR naming the word and offering both working spellings. Silence is the one certainly-wrong answer and it was the behaviour — `pit p : area D4..F6` rendered byte-identical to a document with no pit in it, no mark, no label, no diagnostic, so an author who wrote `area` having just written it for terrain three lines above could only find out by noticing an absence. Refused rather than drawn: the range form already says "these cells", and two spellings for one meaning is a choice the language need not offer. BATTLEMAP ONLY — on a region map an `area` on a feature is a DECLARED OUTLINE (05 §4, ADR 0026) and means something else entirely.
- **A path's ends reach the edges of its terminal cells** (06 §6, #145): a band is drawn through cell CENTRES, so a path drawn only that far stops halfway through the square it was declared to occupy — a road running to a wall, a shoreline or the map edge visibly falls short. The drawn band MUST span its terminal cells, extended along the DIRECTION OF TRAVEL so a diagonal leaves through the corner. Same rule 06 §10 states for lints (a path is its band, and a band is ground) applied to the INK: a road ending at M13 covers M13. Stopping at the centre is NON-CONFORMING and not cosmetic — it makes authors bend documents around it, as Fairwater Manor's King's Road once ran a cell INSIDE the gatehouse so the two would meet, putting a road's band in a building's interior. The DECLARED SPINE is unaffected: cells, crossings and lints keep reading the centres, so a band's own footprint never depends on its stroke width at the ends.
- **Named water** (05 §2, #160): a `zone` in `[water]` names a STRETCH of the sea it sits in — label + at most a faint boundary in the water's tint, NEVER a fill (neither the land tint a `[terrain]` zone drew ON the water nor the opaque sea polygon a `[water]` one drew). Still an ordinary entity: id, `gm=`, `detail=`, referenceable. A zone on land is unchanged. A PASSAGE anchored to the lands it separates is staged (#162).
- **Land is ONE region** (05 §2, #165): a coastline exists only where land meets WATER, so the boundary between two overlapping LAND shapes is NOT drawn — an island touching the shore renders as one continuous coastline with the mainland, two overlapping islands as a single outline. Stroking each land shape's whole outline regardless of what is already land beneath it is NON-CONFORMING (a ring across the peninsula; a lens with a seam). The COMMON case at map scale, not an edge case: a channel narrower than the stroke should read as one landmass (Bainbridge across Rich Passage). Corollary: an island is land in every other sense too — terrain on one is NOT clipped away by the sea it sits in.
- **An island needs water** (05 §2, #164): water wins every overlap and terrain is clipped to land, but ISLANDS are the converse and stay land — an island rises ABOVE the sea that surrounds it. An island whose footprint lies WHOLLY on land is a sentence no map can mean: MUST warn, naming the island. Unreported it draws a stroked contour on open grass with a place-name beside it (9 of 15 islands on the Puget exercise map, silently). The region-map form of 06 §10's door onto solid rock, and easier — a geometric fact, not an inference about intent. AN ISLAND IS SEPARATE, OR IT IS A PENINSULA (ADR 0027) — no third state, and declaring one while the map draws the other MUST be reported. The WEAKER failure matters more (#180): still mostly IN water but TOUCHING the shore, so the union joins the two and the document's island is not one on the map. The test is NAVIGATIONAL — if a body of water large enough to impede navigation exists, the map has to show it; Harstine drawn welded denies Pickering Passage, which boats use, and a map that denies a passage is not functional however it looks. Conformance is stated on the GAP, not the overlap: ANY open water between island and shore = NOT reported, however narrow (a sub-scale gap is still a gap, and a cartographer draws such channels wider than scale to keep the map navigable); an outline that REACHES or CROSSES the shore = reported. The report MUST state the CONTACT not the clearance, and MUST say WHERE it touches and HOW FAR to move to clear it: a share still surrounded by water reads as reassurance (98% sounds clean when the union has already swallowed it), and without a position and a distance the author hunts for the touching end and guesses — several edits instead of one. Same requirement §4 places on a refusal. A WARNING, and the renderer MUST NOT open a channel to repair it — inventing water nobody declared is the same failure as quietly resizing a feature. Author's fixes: widen the channel, move it, or stop calling it an island. A CHANNEL TOO NARROW TO SEE IS DRAWN AS A SYMBOL (ADR 0035, #185 part 2) — the other half of that sentence about sub-scale gaps: where two DISTINCT land regions come within a LEGIBILITY FLOOR of each other with water between, the renderer strokes the medial line of the gap in the colour of the water it lies in, at a minimum width in the SVG's VIEWPORT units, so the passage reads at map scale and shrinks back to its surveyed width as the map is given more room or a viewBox is narrowed onto it. THE LAND DOES NOT MOVE: ink laid over the drawing, no polygon edited, NOT reported (the drawing convention applied uniformly and undone by zoom — the standing a river's symbolic 2-unit width already has; a diagnostic on every narrow passage would bury the welded islands that ARE mistakes). ONE NUMBER is both the gate and the drawn width, which is what makes a channel already wider than the floor untouched — the symbol would fall strictly inside water it already matches; at intrinsic size a user unit IS a viewport unit, so "narrower than the floor" means the same thing in the document and on the screen. A floor in USER units is NON-CONFORMING (they scale with extent:, so the widening survives at depth — the failure this exists to avoid). Convergence is against the SVG's own user-space-to-CSS-pixel scale, NOT page zoom (Ctrl+ scales both together and their ratio never moves). A gap that does not exist is still REPORTED: where two outlines touch the midpoint lands inside one of them and nothing is found, so #180's warning stands rather than the renderer opening water nobody declared — and a welded island therefore gets no help from this. Only a gap between two DISTINCT land regions: a neck within one shore's own ring (a strait between two peninsulas of one landmass, a declared water body thinner than the floor throughout) needs a medial axis, is not what #185 was raised about, and is named rather than left to be discovered. Not a THEME property — a floor a theme could lower is not a floor.
- **A river may not end in open water** (05 §2, #166): "water wins every overlap" is stated for TERRAIN of every kind, so a PATH BAND was exempt by omission rather than by decision — and a river whose end falls inside a water body draws straight across it and out the far side. MUST warn, naming river and body. Warned, NOT clipped: nearly always a typo not a claim, and the fix is a spelling that already works so the diagnostic can name it (`to <coastline> at (…)` / `from <coastline> at (…)`); clipping would also have to carve out bridges, fords, canals and `join`, which touch water on purpose. EITHER END counts — rivers are commonly authored MOUTH-FIRST (from the sea, inland), which is how 9 Puget rivers started offshore in silence. An end declared against a ref, or by `join`, is never questioned.
- **Placed morphology** (05 §4, #93, ADR 0023): cape headland peninsula spit (`morph=jut`) · bay cove sound fjord (`morph=bite`) · island islet atoll oxbow (`morph=detached`). Discrete features ON a line, each a REAL addressable entity — `cape : on coast at (150,182) size=22mi`, `island himling "Himling" : near coast at (95,250) size=8mi`. NO NEW SYNTAX: uses 02 §7's existing `on <ref> at <point>` / `near <ref>` forms. `reach=` gives a word its PROPORTIONS — `size=` is extent ALONG the host, `reach=` how far it carries ACROSS as a multiple of it (calibrated vs Puget Sound #161: cape 0.55 · bay 1 · peninsula 1.6 · cove 3 · spit 5 · sound 6 · fjord 20) · on a DETACHED feature `reach=` is ELONGATION instead (size = long axis, reach = short as a multiple; 1 or absent = a circle) · a jut/bite MAY DECLARE ITS CENTERLINE with `via` (ADR 0026, #169): `on shore at (36,44) via (72,48) (96,92) size=3mi` — a DOGLEG is not a BRANCH (one mouth, one head), so it is not the staged line-branching. A control MAY STATE THE CHANNEL'S WIDTH there — `via (46,64)@1.5mi` (ADR 0030, #190). THAT WIDTH IS THE CROSS-SECTION SQUARE TO THE CENTERLINE (ADR 0033, #192) — the distance between the rails, measured perpendicular at that control; NORMATIVE because the term admits readings differing by more than half again on the same water, and only this one is what a renderer DRAWS (anything else makes the number in the document a different width from the channel on the map, the same objection this section raises against quiet resizing). NOT the largest circle that fits: that reads low where the line sits off-centre (the nearer bank caps it) and HIGH AT A BEND, where the circle settles into the corner and touches both outer banks — 1.17x the true half-width on a square elbow, more as the turn sharpens, making a channel widest exactly where it turns hardest, the one place an offset curve cannot afford it. NOT the narrowest crossing in any direction either: right at a MOUTH, where the chord IS the opening, and anywhere else it finds whatever short crossing lies nearby. without it a feature is a ribbon narrowing monotonically from its mouth, so the opening is always widest, and measured off imagery Hood Canal runs 2.2/3.9/1.3/5.8/1.1mi across down its length — a chain of basins joined by narrows that the ribbon misses by up to 4.04mi against a 1.64mi median. `size=` is the profile's FIRST POINT; an omitted width is INTERPOLATED; interpolation is EASED not straight (straight draws the basins as facets). Stated widths ARE the shape and `taper=` then governs only the generated case (ADR 0026's rule); the head closes on the last stated width. A mouth narrower than the water behind it is a NARROWS and the rails flare — the fillet only CLOSES, its square-root slope being infinite at the mouth (right when narrowing, 148 degrees into the coast when reversed). The declared line REPLACES `reach=` (its own length is the depth) AND its DIRECTION (#175 — the side it runs to is the author's, already said by the first control; the water's side governs only a GENERATED run, and taking it from the map here put the mouth's lead and the declared channel in contradiction, refusing the shape as a fold the author never wrote); both = ERROR. Drawn as a RIBBON along the line, so a straight feature is the two-point case of the same construction. NORMATIVE, both measured as corners on shapes whose own curvature was never sharp: the centerline MUST leave the host PERPENDICULAR (mouth corners are pinned to the host, so a skew builds the fillets in one frame with their ends in another), and sampling MUST answer to the CENTERLINE's curvature as well as the width profile's (a taper=0.15 flank is near-straight and gets 6 samples across its length, striding over the bend) · a jut/bite MAY BE HOSTED ON ANOTHER (#170; Dabob/Quilcene off Hood Canal, Dyes off Sinclair — all previously drew NOTHING, since a bite is spliced into its host's COURSE and a bite is not a course): applied in a SECOND PASS, because a window is measured on its host AS ITS HOST STANDS — and that pass MUST NOT RE-SPACE the curve it is given (#179): normalising a DECLARED course is required, but doing it to a curve already finished throws away outlines sampled at their own radii (1211 vertices to 756, sharpest turn 29° to 82°) and lands samples by TOTAL ARC LENGTH, so an unrelated feature elsewhere turned a drawable arm into a fold. A feature's shape MUST NOT depend on what else the map contains; water side comes from the HOST not the map (`sea : west of hood` is not a sentence about a canal — the canal IS water), i.e. the direction to the host's own centerline (ADR 0024's ask-the-containing-feature, asked by a bite) — and the HOST'S ANSWER TAKES PRECEDENCE rather than filling in where the map is silent: consulted second, the map's global guess arrives first and the host is never asked, which left one of a canal's two banks refusing every arm because that guess drove the bite inward there; where that host DECLARES its centerline that line is the whole answer and the host's own water side is not consulted — requiring one anyway dropped arms whose course was already stated, making them depend on how a sea two features away was spelled (#175). Declaration order not significant. AN ANCHOR ON THE HOST'S CENTERLINE MUST BE REFUSED (#191, ADR 0031): the side is a direction TOWARD that centerline, so on the line there is no direction and the document has not said which bank — and that IS the anchor an author reaches for, one of the host's own via controls, because that is the point on the canal they mean. Unreported, the bank fell to whichever of the host's two rails a vertex rounding picked: the rails measured 0.752mi from the anchor APIECE and answered differently, and refusals ALTERNATED along the canal while ignoring the feature's size entirely (a refusal that does not move when the feature is shrunk to a third is not about its size). A renderer MUST NOT PICK — a bank chosen by sampling can be switched by an unrelated feature elsewhere, the silent shape-change #179 forbids, and a bay that changes banks without a word is worse than one that will not draw. MUST name the ambiguity and give BOTH banks, since naming one is the same silent pick in prose. The threshold is FLOAT NOISE only: swept perpendicular to a 2mi canal, an anchor 0.001mi off the centerline already answers stably and identically out to the bank, so a coordinate states a side as soon as it is not ON the line · a placed feature is LABELLED ON ITS BODY (#171) at the arc-length midpoint of its centerline (07 §5's line rule): the anchor is a point on the HOST, so labelling there names a 40mi canal at its mouth and piles several inlets' names into one spot — which also defeats 07 §5's crowding machinery rather than exercising it · a detached feature MAY CARRY ITS OWN OUTLINE (ADR 0026, #172): an `area` on the entity line, points FRAMED as offsets from the anchor (ADR 0009's referent frame) so moving it is ONE coordinate and it stays attached to its host; ORGANICALLY FINISHED like any declared silhouette (raw reads as a surveyed polygon). Dials are the SHORT FORM and produce a lozenge — right for the anonymous islet ADR 0023 is written around, wrong for Whidbey, which doglegs; shape was the one thing about a feature that could not be declared. Outline AND dials = ERROR (honouring either discards the other; a renderer that silently picks is the failure this prevents) — only ENTITY-LINE pairs count, an inherited `reach=` is not a conflict; <3 points reported. A JUT/BITE takes no outline (its shape must join its host at two points and stay joined) — it declares a CENTERLINE instead, staged #169 · and the long axis is INFERRED not declared — a long island parallels the WATER IT SITS IN (#159) · which water: where the anchor lies inside a `bite` the axis follows THAT CHANNEL, else the host's local course (ADR 0024, #167). On an open coast the two agree; inside an inlet the host is the COASTLINE, running ACROSS the inlet, so an island placed in one drew as a bar damming the channel instead of splitting it. This is what lets land DIVIDE WATER (Hartstene making Case Inlet and Pickering Passage two inlets) with NO placement form of its own. Smallest containing channel wins (more specific). MUST read the containing feature's OWN DECLARATION, never the rendered water: measuring the drawn sea gives the same answer but makes an island's shape depend on rendered geometry, so an unrelated coastline edit could silently re-point a named island — ADR 0023 forbids it · `taper=` says HOW FAR the sides converge and over how much of the DEPTH (1 = a wedge, lower = parallel flanks ending in a broad round bight — a fjord is a drowned valley, and at wedge profile the only way to its depth was a needle, #158; a constant head-width is NON-CONFORMING, it leaves taper choosing only WHERE the neck falls and a fjord still comes out a spearpoint, #163) · direction comes from the water and an ENCLOSED sea declares it by SHAPE: a bounded body given as an area following its coasts settles the side, since a half-plane can only describe an open ocean (#157); a vocabulary facet, so derivation carries it and an entity may override. Without it the words were decorative — cove/sound/fjord drew the SAME shape at the same size. `morph=` is a CLOSED set saying what the geometry does to the host; the WORD says what the thing is and is what a theme colours — independent on purpose, so `bay` bites while being water and `oxbow` detaches while being water. Direction is INFERRED from which side the water lies on WHERE NOTHING DECLARES IT (a declared centerline states its own; an arm takes its host's) — and the inference may NOT be one vector for a whole body reduced to a sign against the local normal: that is inverted on a shore wrapping a peninsula and undecidable where the coast turns square to it, leaving the side to arithmetic noise; undetermined = the feature MUST BE REPORTED AND NOT DRAWN (#175, #178) — warning and then placing it on the global answer anyway is the worst of both (the message says the map does not decide this spot, the shape is drawn as though it did): measured on a shore wrapping a peninsula under `sea : east of shore`, a bay drew EIGHT MILES OUT INTO THE SEA on the western limb. Resolve LOCALLY from the water's outline, at the nearest point ON the course not its nearest declared VERTEX — a `from … to` course has two vertices, so the nearest to any anchor is an END of the coast and the probe samples a corner of the map instead of beside the feature. A feature stating its own course is unaffected, having already said which way it runs. Geometry is a pure function of (kind, anchor, size), independent of `seed:` and of every other entity. PROMOTION IS GEOMETRY-STABLE: adding an id/name MUST NOT move the shape. A feature is drawn at its DECLARED size or reported — never quietly resized: clamping is non-conforming because it makes `size=` a lie (the same 90mi cape would differ by stretch). Cannot-draw = ERROR naming feature, size and host, course left undisturbed, AND naming WHICH of FIVE causes (each has a different fix): FOLD (smaller size=/reach=, straighter stretch) · OFF-END (half the mouth past the end of the host — move it along) · OVERLAP (another feature claims the stretch — name it too) · OFF-NORMAL (#183: a declared centerline leaving at a skew, where squaring the first control onto the normal WOULD draw — the cause an author meets first, since the perpendicular cannot be judged by eye on a curved shore; MUST give the angle and MUST NOT quote size=, which is the wrong edit. Determined by TRYING the squared control, not by thresholding the angle — what bites depends on mouth width and first-leg length. Where the trial DRAWS, that control is offered and is a fact rather than an estimate; WHERE IT DOES NOT, THE CAUSE IS STILL THE SKEW (#194) — a large departure is precisely what one squared control cannot rescue, and calling it a fold or a pinch sends an author to spread via points through a bend they never wrote, the corner being between the renderer's OWN mouth lead and their first control. Then MUST give BOTH BEARINGS (where the centerline leaves, where the host faces) and MUST NOT offer a coordinate, none being known to draw. The two are told apart BY POSITION not by angle: everything before the author's first control is mouth and generated lead, so a fold there is not theirs; one past it is) · PINCH (#189: the centerline turns TIGHTER THAN THE CHANNEL IS WIDE — the radius rule below binding on the author's own line rather than on the host's, and the cause a MEASURED centerline meets, since measurement crowds controls where curvature is high and a cluster describes a turn of its own spacing's radius. MUST give WHERE, the radius there and the width there — a fold is LOCAL, and on a canal stated in eight controls there is no reading the offending bend off a list of coordinates — and MUST NOT quote size=, since where a profile is declared the width that folds is not size= at all). Two features may NOT occupy one stretch: blending them silently puts a corner between two features each drawable alone (#163). Reporting one cause as another is non-conforming. The course may not cross itself AND may not fold to a cusp (simplicity alone is insufficient — a fold draws a spike without intersecting). What refuses a BEND is its RADIUS against the half-width, never its TOTAL TURN (#177): folding is the LOCAL offset-curve condition, and cumulative heading is no proxy — a circle of any radius accumulates 360. A bound on the total is NON-CONFORMING: it refuses a bend of many times the half-width for the same total as a hairpin, and closes the one technique the geometry suggests — taking a tight corner as a series of gentler angles separated by distance, which is how a waterway of finite width turns (an oxbow is most of a full circle). HOW MANY CONTROLS STATE A CENTERLINE MUST NOT CHANGE ITS SHAPE (#189) — §4's rule for a declared HOST course (#154/#155: collinear points on a straight coast doubled the deepest drawable feature until it was normalised), asked of the feature's own line. It binds on the SPLINE'S PARAMETERISATION: a uniform Catmull-Rom gives every span an equal share of the parameter however long it is, so a short span beside a long one is traversed at a wildly different speed and the curve bulges past it. Measured on a traced canal — three controls within a mile at a bend, then a ten-mile run — that bulge put ONE SELF-CROSSING and a 54.9-degree kink in a line written as smooth, so the shape was refused at EVERY size from 1.56mi down to 0.3mi while the same shape in two evenly spread controls drew at full size (the fold was real, the refusal honest, the CAUSE the parameterisation). CENTRIPETAL knots (spaced by chord length) are sufficient and are a GUARANTEE not a tuning — such a spline cannot cusp or self-intersect within a span — and cost nothing where controls are already even, since equal chords make equal knots and that IS the uniform spline. A measuring tool MUST NOT have to space its controls evenly to make its own output drawable: that thinning deletes exactly the controls a bend is made of (on Hood Canal it refused above 1.2mi where the unthinned line drew at 2.2). The DRAWN OUTPUT MUST CARRY THE SHAPE THAT WAS CHECKED (#176): two vertices closer than the output's precision print as one point, and a zero-length segment has NO DIRECTION, so anything measuring the drawn curve reads an arbitrary angle — a smooth 29-degree curve measured 155.9. Emitting one is non-conforming (it makes a curve that passed every check appear to violate it, indistinguishable from a real cusp); sampling finer than the output can express buys nothing and costs exactly this. A feature is an OUTLINE spliced into the host — mouth fillet (so the mouth is the widest part and its corner has a radius) · flanks · ROUNDED HEAD (never a point or a chord) — sampled by its own radii. Depth-as-a-function-of-position (a raised cosine over a window, i.e. a GRAPH) is NON-CONFORMING: a graph cannot have parallel sides, so a fjord's depth within its mouth width forces a radius of curvature 200x finer than any affordable sampling and every inlet drew as a 60-90 degree polygon while passing every fold check (#163). The whole feature travels ONE direction (the host normal at the anchor), never a per-point offset: per-point normals pinch on a headland and make drawable bays undrawable. 02 §9's noise-free spline is AFFIRMED, not revised. Line-BRANCHING (`delta`, `fork`) is staged and deliberately NOT in the stdlib yet, so it gets unknown-word treatment rather than a declaration that parses clean and draws nothing

## Themes (spec 08)

A theme is a Chartdown document of `[theme]` + `[glyphs]` sections (no `map:`). `[theme]` lines: `<subject> : <pairs>` where subject = vocabulary word (chain-resolved) · `word.state` · zone `word.core`/`word.edge` (IMPLEMENTED both ways, #150: on AREAS/blobs/ridges `edge` is the boundary band and `core` the interior; on PATH BANDS `edge` is the two side margins and `core` the centre strip — foothills are `mountains.edge`. Declaring one zone leaves the other the word's plain fill. A zone counts as declared only from an explicit `word.edge`/`word.core` entry — the chain fallback would make every word look zoned) · `side.<word>` · surface (`paper grid fog ink light ledge leader`; each is ONE colour reading exactly one property — `fill` for paper/fog/ink/light, `stroke` for grid/ledge/leader; anything else on a surface is inert and reported, and a surface has no zones and no states). Closed pairs: `fill stroke width dash opacity glyph asset edge bank. `bank=` is which side of its own line a border's ink lies on — land|water|both, CLOSED (ADR 0034, #185): a stroke CENTRED on a boundary puts half its ink each side and WHICH half is unanswerable, so two approaching shores fill the passage between them — the channel is not thin, it is PAINTED OVER, and #180 cannot catch it (that check reasons about geometry; a theme can erase a channel the checker just certified). NO SPELLING for a midline stroke: `bank=both` is the opt-in and owns the result. Each stroke MUST be CLIPPED to the region it belongs to, which is what makes theme freedom safe — a bold water-side vignette bleeding across a channel paints WATER-COLOURED ink onto WATER, so it darkens and never becomes land; a theme may make a map ugly, never wrong. Hence NO STROKE PAINTS LAND COLOUR ONTO DECLARED WATER. Default `land`, by arithmetic not convention: a coastline is dark ink not a vignette, 1.2 units on a 200mi map spans 0.29mi, so two shores 0.20mi apart paint their channel shut; clipped to WATER it is worse (0.29mi each side); clipped to LAND it puts nothing in the water. Does NOT rescue a SUB-PIXEL channel — that is the LEGIBILITY FLOOR of 05 §2 (ADR 0035), a renderer convention and deliberately NOT a theme pair`. `[glyphs]`: `name : "SVG path"` in a 24×24 origin-centered box. `glyph=`/`asset=` take comma-separated variant pools chosen by deterministic position hash. Inheritance: `use:` + shadowing (`use: default` = built-in). A map's `theme:` is a suggestion; the renderer/user wins. DEAD DECLARATIONS (08 §6, #116, ADR 0022, always WARNINGS, no suppression syntax): a `[theme]` subject NO entity resolves to (usually a misspelling) · a subject that DOES resolve whose properties are never read for those entities (`chain : stroke=` with 4 chains on the map) · a SURFACE (`paper` `ink` `fog` …) whose property is never read (no entity ever resolves to a surface) · a `[glyphs]` name no `glyph=`/`asset=` references · a `glyph=`/`asset=` naming a glyph NO `[glyphs]` section defines (#149 — checked against the DECLARED pool not what this render drew, since the pick is a position hash; defined in ANY layer counts; liveness alone cannot see it, because the lookup returns the NAME and registers a read while the miss happens later in the glyph table). The three subject messages MUST differ: the first means "you misspelled something", the rest "nothing you write here will help", and "does this subject resolve?" is a fact about the DOCUMENT the theme cannot answer from its own hits (#148). Scope: only the SELECTED theme (§5's shadowing puts it LAST in the layering, so no separate declaration is needed); inherited and built-in themes are exempt because a shared theme deliberately styles words no one map uses. Liveness is PER PROPERTY not per subject (default + user both carry `water`; their pairs merge, so a subject-level hit would call a dead `glyph=` live). Theme diagnostics carry a line in the THEME file and MUST be reported against the theme's path. Same scope rule for `[vocab]` (04 §3): a word this document neither carries nor derives from warns; `use:`-imported library words and a vocabulary DOCUMENT's own words never do — "unknown words never fail" covers the author who never promised, not a promise that was broken.
